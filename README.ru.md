## 🌟 Описание

TarsSecureGuard — это **ориентированный на локальную работу (local-first) ИИ-шлюз, то есть маршрутизатор эпохи ИИ**. Он находится между вами и всеми возможностями ИИ: слева находятся ваши ИИ-приложения (Claude Desktop, Cursor, Cline, Windsurf, Codex CLI … — выбирайте любые), справа 24 облачных провайдеров моделей + 8 локальных сред инференса (подключайте любые); внешне предоставляет совместимую с OpenAI конечную точку (HTTP или **stdio**) + MCP, внутри обеспечивает унифицированную оркестрацию, управление и аудит.

> Домашний роутер не производит сетевые кабели и не создаёт сайты — он позволяет каждому устройству безопасно выходить в интернет. TarsSecureGuard не производит модели и не навязывает вам использование какого-то конкретного клиента — **он позволяет каждому ИИ-клиенту безопасно работать с любой моделью**. Мы хотим довести эту функцию до совершенства: всё, что можно подключить, будет подключено, а для всего, с чем подключение пока недоступно, мы предоставляем готовый к исполнению список действий для интеграции (см. `docs/v3.2.0-unconnectable.md`).

### Новое в v3.2.0 · концепция Universal Connector

> **Одна подписка на Coding Plan = ключ от всех моделей**. TSG скрывает различия между разными провайдерами за слоем совместимости с OpenAI, ИИ-клиентам не требуется переделка, пользователям не нужно переключаться между инструментами.

Существует три **варианта интеграции** для подключения всех существующих в мире ИИ-приложений (в том числе открытого / закрытого / CLI-программного обеспечения, с которым нельзя подключиться напрямую) к TSG:

| Режим | Подходит для | Реализация |
|---|---|---|
| **embed (встраивание)** | Библиотеки с открытым исходным кодом (C/C++/Go/Rust/Python) | Код компилируется непосредственно в процесс TSG и вызывается напрямую (например, ggml / whisper.cpp / sqlite-vec) |
| **federate (федерация)** | Удалённые сервисы / API-шлюзы | Унифицированная оркестрация через обратный прокси TSG + адаптацию протокола (различные MCP Hub, сторонние API-платформы) |
| **wrap-cli-as-mcp (упаковка CLI в MCP)** | Любые инструменты командной строки | Упаковка в MCP-сервер без необходимости написания кода, ИИ вызывает их косвенно через TSG (например, ripgrep / fd / magika / jq) |

**Текущий прогресс**: 24 облачных провайдера + 8 локальных сред инференса (встроенная регистрация, для каждого провайдера есть машиночитаемый профиль), руководства по подключению 13 клиентов, список из 17 компонентов, с которыми подключение пока недоступно (цель для v3.3.0 — 50 интеграций). **Добавление нового провайдера требует только изменения конфигурации, корректировка кода не нужна** — именно поэтому v3.2.0 может выполнять роль «маршрутизатора».

## 🧩 Обзор возможностей v3.0.0 («Ремень безопасности для вашего ИИ»)

### Линия A · Охранитель ресурсов (resourceGuardian)
- Мягкий лимит памяти `GOMEMLIMIT` (min(10% физической памяти, 384 МБ), для экономичного режима eco — 128 МБ, значение можно переопределить).
- **Многоуровневый отклик L0–L3**: L1 — деградация некритических функций → L2 — отключение ресурсоёмких функций → L3 — корректное завершение работы (ожидание завершения запросов в течение 30 секунд + сброс данных аудита на диск + сохранение состояния + код выхода 42 + охлаждение для предотвращения шторма запросов).
- Определение необходимости срабатывания L2/L3 по **показателю RSS**, что позволяет обнаруживать утечки памяти в CGO / внешних компонентах; экономичный режим eco автоматически применяется для оборудования категории D.

### Линия B · Улучшенная защита
- **Семантическое обнаружение с分级ным перенаправлением трафика (semanticGuard)**: сначала срабатывают статические правила, подозрительный трафик отправляется на проверку локальной модели размером 0,5B–1,5B; **непререкаемое правило fail-close** — при недоступности движка сразу возвращается ошибка 503, трафик ни в коем случае не пропускается; кэширование отпечатков + ограничение скорости для подозрительного трафика.
- **Трёхмерное ограничение скорости по алгоритму «токенового ведра» (rateLimiter)**: IP × тип конечной точки / Ключ × тип конечной точки / общий объём трафика по IP, при превышении лимита возвращается код 429 и начисляется штраф к репутации.
- **Локальная репутация IP (ipReputation)**: начальный балл — 100, штрафы начисляются за срабатывания WAF / сканирование / превышение лимитов, низкий балл автоматически приводит к блокировке, поддерживаются белые списки, автоматическое восстановление через 24 часа, оповещения об аномалиях NAT, разблокировка администратором.
- Непререкаемое правило одностороннего слияния «**ИИ может только ужесточать требования**»: политики безопасности могут только становиться строже, 100% покрытие модульными тестами + аудит во время выполнения.

### Линия C · Двухэтапная умная маршрутизация
- **smartRouter**: приоритет отдаётся статическим правилам как гарантийному механизму + **ε-жадный бандит (ε-greedy bandit)** (ε уменьшается от 0,1 до 0,02), автоматический выбор оптимального бэкенда на основе истории успешности запросов / задержек; обратная связь не от администраторов имеет пониженный вес для предотвращения подделок.
- **scoreBoard**: баллы, рассчитанные во время выполнения (успешность × задержка), совмещаются с результатами офлайн-оценки **lm-eval-harness** (относительная справка, честная разметка; вспомогательный компонент на Python подключается по необходимости, не является обязательным).

### Линия D · Повышение позиции в экосистеме
- **`--mcp-stdio`: JSON-RPC 2.0 через stdio**, любой локальный агент получает полный набор средств защиты сразу после подключения — ключевое конкурентное преимущество данной версии.
- Инструменты: `tars_guarded_chat` / `tars_guard_status` / `tars_route_preview` / `tars_model_score` / `tars_module_schema` / `tars_ip_reputation_unban`; для административных операций требуется `TSG_ADMIN_KEY`, все действия полностью контролируются аудитом.

### Линия E · Инженерия стабильности
- Полное покрытие обработкой паники; фазз-тестирование на Go (WAF / разбор конфигурации / семантическая нормализация); **скрипт нагрузочного тестирования на 8 часов непрерывной работы** (`soak.sh` / `soak.ps1`); модульные тесты + интеграционные тесты httptest с флагом `-race` проходят без ошибок.

### Платформы и доставка
- Полностью русифицированный интерфейс; **полный набор файлов для развёртывания**: юнит для systemd, Dockerfile, docker-compose (rootless), пример sidecar для K8s, LaunchDaemon для macOS (см. [`deploy/`](./deploy)).
- `go.mod` не имеет сторонних зависимостей, используется только стандартная библиотека — **нулевая поверхность атаки через цепочку поставок**.

## 🚀 Быстрый старт

### Установка в один клик (рекомендуется, автоматически определяет систему и архитектуру)
```sh
# macOS / Linux
curl -fsSL https://raw.githubusercontent.com/HP-jh/TarsSecureGuard/main/install.sh | sh
```
```powershell
# Windows PowerShell
irm https://raw.githubusercontent.com/HP-jh/TarsSecureGuard/main/install.ps1 | iex
```
После установки запустите `tsg` для запуска шлюза, панель управления автоматически откроется по адресу `http://127.0.0.1:18889`; команда `tsg doctor` запускает самодиагностику окружения. Также можно скачать универсальный установочный пакет `tsg-setup.zip` (содержит установщики для всех платформ, после запуска автоматически адаптируется к системе).

### Запуск из исходного кода
```sh
git clone https://github.com/HP-jh/TarsSecureGuard && cd TarsSecureGuard
go run .          # или ./start.sh (для Windows дважды кликните по start.bat)
```

Ранее к 8 REST-точкам управления нельзя было обратиться через интерфейс, только через curl. Экспорт данных аудита выполняется через загрузку blob с заголовком аутентификации (ключ не отображается в URL); также исправлен сдвиг бейджа версии в боковом меню, появившийся начиная с v3.2.2. Все сквозные тесты в безголовом режиме Playwright + Chromium проходят успешно, интерфейс не имеет привилегий, контроль за аудитом не ослабляется. Подробнее в [docs/v3.2.4-ui.md](./docs/v3.2.4-ui.md).

### Обновление производительности v2 (v3.2.3)
**Однопроходное объединение регулярных выражений в WAF + предварительная фильтрация по триггерным байтам ASCII** (для режимов normal/strict используется одно объединённое регулярное выражение для быстрой однопроходной проверки, при совпадении выполняется обратный поиск для определения имени правила, семантика не изменяется; для текстов полностью на русском языке проверка регулярным выражением не выполняется, скорость сканирования в режиме strict увеличилась на 99,8%), **однопроходная маскировка ПД** (четыре режима объединены в одну замену, скорость увеличилась на 15%), **16 сегментированных блокировок кэша ответов** (сегментация по FNV-1a, независимые mutex + LRU, скорость параллельных операций get/put увеличилась на 10% на 2 ядрах) — кандидаты на оптимизацию были поштучно изучены: отклонены варианты с JSON sync.Pool и пакетной фиксацией данных аудита (порядок записи совпадает с порядком хэш-цепочки, асинхронная запись создаёт риск разрыва цепи), подтверждено отсутствие пути SSE (не существует в коде). Подробнее в [docs/v3.2.3-performance.md](./docs/v3.2.3-performance.md).

### Уровень управления + обновление производительности v1 (v3.2.2)
**Общая память** (три уровня пространств имён: пользователь → арендатор → глобальный, цепочка разрешения с переопределением по принципу ближайшего значения, изоляция арендаторов обеспечивается нормализацией пространств имён), **общая информация** (структурированные записи знаний типа fact/preference/note/link + поиск по весу), **MCP расширения контекста** (сборка пакета контекста с определённым содержимым из идентификаторов и политик + общей информации + общей памяти, инжектируемое содержимое и пользовательский ввод проходят через одну и ту же цепочку безопасности), **подключение корпоративных провайдеров идентификации OAuth/OIDC** (Authorization Code + PKCE, вручную написанная проверка подписи RS256/ES256 на стандартной библиотеке, режим fail-close, сессии используют точно такую же матрицу RBAC, как и локальные пользователи), **привратник** (защита на уровне действий перед выполнением инструментов: запрет изменения конфигурации безопасности, запрет доступа к чувствительным путям, двухэтапное подтверждение для высокорисковых операций, предотвращение подделки инжекции идентификаторов, конфигурация только на ужесточение правил), **хэш-цепочка аудита v2** (SHA256 для связей между записями, ежедневная ротация файлов, возобновление цепочки после перезапуска, полный перерасчёт цепочки для предотвращения подделок) — подробнее в [docs/v3.2.2-governance.md](./docs/v3.2.2-governance.md). Также есть **обновление производительности v1**: постоянный дескриптор файла логов для конвейерной записи (скорость записи одной строки на диск увеличилась на 79%), дополненное покрытие пула подключений (пул для проверки doctor / параметры customToolClient выровнены с сохранением изоляции SSRF), предкомпиляция регулярных выражений первого уровня на уровне пакета — подробнее в [docs/v3.2.2-performance.md](./docs/v3.2.2-performance.md).

### Десктопный клиент (добавлен в v3.2.1, не требует браузера)

## 🥊 Анализ главных конкурентов

**Вывод: текущий крупнейший конкурент, на который нужно прежде всего реагировать, — это LiteLLM** (фактический стандарт открытых AI-шлюзов, около 60 тыс. звезд на GitHub, самая развитая экосистема и узнаваемость на рынке); на внутреннем рынке Китая **New API / One API** являются лидерами по узнаваемости решений на стеке Go; по позиционированию "локальный приоритет" ближайшим аналогом является **OmniRoute**.

| Конкурент | Преимущества | Недостатки по сравнению с TarsSecureGuard |
|-----------|--------------|-------------------------------------------|
| **LiteLLM** (главный конкурент) | Самая широкая поддержка провайдеров, зрелая экосистема, проработанная система виртуальных ключей/бюджета/повторных запросов, первое место по узнаваемости за рубежом | Технологический стек на Python, тяжелое развертывание (требует Postgres + Redis, размер образа более 500 МБ, полный комплект занимает почти 1 ГБ); ориентация на облачные модели; безопасность не является ключевым преимуществом по умолчанию; нет версии в виде одного файла, готового к работе после распаковки; нет семантической политики fail-close / демона защиты ресурсов |
| **New API / One API** (лидеры на внутреннем рынке Китая) | Написаны на Go, полная поддержка отечественных моделей, законченный цикл работы с каналами/токенами/тарификацией/пополнением счета | Позиционируются как решение для "перепродажи API/операционной тарификации", требуют MySQL + Redis; большое количество сложных параметров; не предназначены для сценариев с локальными моделями / безопасности на отдельном сервере |
| **OmniRoute** (ориентирован на локальную работу) | Четкое позиционирование local-first, быстрый рост количества звезд на GitHub, автоматическое понижение уровня сервиса и множество стратегий маршрутизации | Смещен в сторону "агрегации маршрутизации от нескольких поставщиков", безопасное управление (WAF/семантика/RBAC/ограничение скорости/репутация IP/аудит/PII) не является его ядром; соответствие требованиям внутренней сети с нулевой зависимостью в виде одного файла не является его приоритетом |
| **LM Studio / Ollama + OpenWebUI** ("достаточные" альтернативы) | Часто уже установлены у пользователей, удобный графический интерфейс, простой поиск моделей | Это **среды выполнения**, а не шлюзы управления: не предоставляют WAF, семантическую защиту, ограничение скорости, репутацию IP, RBAC, аудит, демона защиты ресурсов — TarsSecureGuard как раз управляет этими решениями и дополняет недостающий уровень функциональности |

**Стратегия дифференциации**: не конкурировать по "количеству поддерживаемых провайдеров", а занять недооцененную нишу, крайне важную для обычных пользователей и внутренних корпоративных сетей — **«нулевая конфигурация + один файл + безопасность включена по умолчанию + локальный приоритет + защита из коробки через stdio»**. Тяжелые шлюзы предназначены для крупных компаний с отдельными платформенными командами; TarsSecureGuard предназначен для обычных пользователей, гиков и изолированных внутренних сетей, которые хотят начать безопасно и стабильно использовать локальный ИИ "прямо сейчас".

## 🏰 Анализ самого надежного конкурентного преимущества

**Вывод: основное конкурентное преимущество — это активы доверия и база знаний по защите LLM, накопленные в «Security Core», которые постоянно укрепляются за счет архитектуры решения в виде одного файла без зависимостей с минимальной поверхностью атаки; реализация MCP stdio в версии v3.0 позволяет автоматически распространять这套 защиту при интеграции, дополнительно расширяя преимущество.**

Конкурентное преимущество состоит из трех уровней от самого поверхностного до глубокого:

1. **Уровень простоты инженерной реализации (легко копируется, краткосрочное преимущество)**: нулевые сторонние зависимости, чисто статический один файл, поддержка шести платформ, демон защиты ресурсов и интеллектуальная маршрутизация. Конкуренты могут скопировать это, но для этого нужно долго ограничивать функциональность и отказываться от расширения экосистемы — большинство команд не пойдут на это.

2. **Уровень знаний в области безопасности (основной барьер, растет со временем)**: Security Core — это полный набор **защитных активов для LLM** — WAF и сигнатуры для обнаружения инъекций/джейлбрейка в промптах, определение семантических серых зон (fail-close), отпечатки поведения для оценки репутации IP, трехмерное ограничение скорости, шаблоны PII и их маскировка, пять правил защиты от SSRF, интеграция с брандмауэрами, система аудита, а также постоянная оптимизация баланса "уровень обнаружения vs уровень ложных срабатываний". **Чем больше реальных образцов → тем точнее правила → тем меньше ложных срабатываний → тем больше пользователей → тем больше образцов** — это самоподкрепляющийся цикл, который новые игроки не могут скопировать за один раз просто украв код.

3. **Уровень доверия и распространения (самый глубокий, сложнее всего копируется)**: Конечный барьер для продуктов безопасности — это **репутация "никогда не было инцидентов"** и узнаваемость как соответствующего стандартам безопасности решения; обязательство по дизайну "безопасность никогда не отключается / для ИИ защита может только ужесточаться" закрепляет статус выбора по умолчанию. Функция **«защита из коробки через stdio»** в версии v3.0 означает, что любой локальный агент при интеграции автоматически наследует весь набор защитных функций — возможности защиты автоматически распространяются вместе с интеграциями, образуя **цикл распространения**. Подписка монетизирует доверие за счет постоянных обновлений безопасности и SLA. Доверие невозможно построить за квартал и невозможно разрушить ценовыми войнами.

> **Честная оценка**: проект находится на стадии активного роста, его конкурентное преимущество все еще "расширяется" — функциональная часть может быть скопирована. Реальная ширина преимущества определяется **данными защиты, полученными за счет большого количества внедрений + циклом распространения через stdio + долгой репутацией без инцидентов**. Стратегическая ценность подписочной версии как раз в том, чтобы превратить "постоянные обновления безопасности" в актив, который дает повторяющийся доход, приносит прибыль и накапливает доверие пользователей.
