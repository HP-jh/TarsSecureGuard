# TarsSecureGuard v3.0.4 升级说明：零信任深化与多租户 RBAC

> 依据：锦衣卫裁定 TSG-ZT-MT-2026-0929（四节红线 + 五个剩余问题）
> 约束遵守：security-core 未动（WAF/鉴权链/审计骨架原样）；WAF 规则零改动；未引入新模块（新代码均在 package main 内：whitelist.go / tenant.go + 既有文件接线）。

## 一、升级行为变化（存量用户必读）

1. **默认密钥通道（"tars-gateway-key"）**：
   - 全新安装：首次启动自动写入 `"security": { "defaultKeyAllowed": true }`（通道显式化，小白体验不变）。
   - 存量升级：若仍在用默认密钥且未显式 `defaultKeyAllowed: true` → 启动即自动轮换为 32 字节随机密钥，明文写入安装目录 `gateway-key.txt`（0600），旧默认密钥立即失效；审计 `WHITELIST_REMOVE` + `SECURITY_KEY_ROTATED`。前端首次请求 401 时按提示输入新密钥即可。
   - 单机单用户想保留默认密钥：config.json 显式写 `"defaultKeyAllowed": true` 并重启。
2. **IP 信誉白名单**：只接受精确 IP；CIDR（如 192.168.0.0/16）、通配（10.*.*.*）一律剔除并审计 `WHITELIST_INVALID_ENTRY`。
3. **文件授权根（allowedRoots）**：必须绝对路径且无通配符；相对路径/通配被剔除。Desktop/Documents/Downloads 自动填充行为保留，但均以绝对路径显式落盘。
4. **MCP 外置服务器 / sidecar 钉扎**：仅 `enabled: true` 的条目计入放行集（既有行为显式化）；无显式 enable 的条目不再放行。
5. **白名单完整性基线**：安装目录 `whitelist-integrity.json`（0600）记录各动态白名单的 SHA-256；失配时回退基线条目并审计 `WHITELIST_INTEGRITY_FAIL`/`WHITELIST_INTEGRITY_ROLLBACK`（拒绝加载新值，不降级）。删除该文件 = 重建基线（首次部署时）。

## 二、多租户模型（user / group / role 三层）

角色（零自动继承，7 角色 × 9 端点类矩阵逐格授权）：

| 角色 | 租户 | 能力 | 天花板 |
|---|---|---|---|
| global_admin | * | 全部端点 + 跨租户查询（记 AUDIT_CROSS_TENANT_ACCESS） | 唯一可写安全项的角色 |
| global_auditor | * | 全部只读 + 审计 | 一切写请求入口层硬拒 |
| admin | 本租户 | 本租户运营项读写 + 本租户审计 | 安全项写（config API）须 global_admin |
| team_lead | 本租户本组 | chat/工具/本组审计只读 | 零管理面写权限（防自授权） |
| auditor | 本租户 | 本租户只读审计 | 一切写请求入口层硬拒 |
| user | 本租户 | chat/工具/搜索 | 无 admin/audit/tenant 面板 |
| readonly | 本租户 | GET-only（chat 类 GET 除外全部只读） | 所有写方法拒绝 |

单管理员回退模式（无 users 表）：自动映射 global_admin、租户 "*"（裁定五-5 备案）。

## 三、配额与策略

- **三层日配额**：租户 tokensPerDay → 用户 tokensPerUserPerDay → 组 tokensPerGroupPerDay；chat 类请求前置 `quotaCheck`（超限 429 + `QUOTA_EXCEEDED` 审计），成功请求 `quotaRecord`（tokens ≈ 字符数/4）。用量持久化 `data/quota-usage.json`（0600，隔日作废，重启恢复）。
- **全局硬上限**：`globalTokenCapPerDay ≥ Σ各租户 tokensPerDay`（校验拒绝）；全局上限下调触发自动级联收紧（`TEAM_CONFIG_CASCADE_CLAMP`，剩余问题 3 备案方案）。
- **路由偏好**：租户/组 `preferredBackends ⊆ {llama, lmstudio, ollama}`；组优先于租户；缺省取全集（Rule A）。
- **限流**：租户阈值只许比全局更严（放宽 → `TEAM_CONFIG_SCHEMA_FAIL`）；生效为第 4 维（租户×端点类）叠加在三维令牌桶上。
- **冲突规则 A/B/C/D**：代码层硬编码（无值取全集 / 组优先租户 / 用户/组 ≤ 租户 / 安全面全局优先不可覆盖），禁合并语义。

## 四、按组 audit 视图

- `GET /api/admin/audit-logs`：行级强制过滤（TENANT=/GROUP= 字段；旧行归 "system"）。admin/auditor 本租户；team_lead 本租户本组；global 角色全量，`?tenant=x` 定向跨租户查询记 `AUDIT_CROSS_TENANT_ACCESS`。
- `GET /api/admin/audit/group-summary[?tenant=&group=]`：按组聚合当日审计计数（team_lead 自动限定本组）。
- `GET /api/admin/tenants/status`：租户面板（配额用量 usedToday、组数、路由偏好；global 看全部、其他仅本租户）。
- `GET /api/admin/whitelist/status`：零信任白名单注册表（动态 kinds 完整性状态 + 静态清单）。

## 五、配置变更通道（防越权）

- API `POST /api/admin/config` 白名单不含 tenants / users / security.apiKey / defaultKeyAllowed / 白名单类路径——试图修改记 `CONFIG_REJECTED`（仅 global_admin 可用该 API）。
- 租户/用户/白名单变更一律走 config.json（2 秒热重载）：校验失败保持上一版本生效（`TEAM_CONFIG_SCHEMA_FAIL`），成功原子替换（`TEAM_CONFIG_APPLY`，含前后 SHA-256）；用户表校验失败回退上一版本有效用户表（`RBAC_USERS_ROLLBACK`）。

## 六、裁定五节剩余问题的备案方案（实装阶段产出）

1. **MCP 租户上下文**：MCP stdio 为单用户进程级——租户上下文由 TSG_ADMIN_KEY 持有者（global_admin）决定；team 场景建议每租户独立 TSG 实例。后续版本评估 MCP 会话头带租户。
2. **sidecar 隔离**：sidecar 模块经 /api/ext 反代时全链路过网关（WAF/RBAC/审计已按请求身份判定）；模块级租户绑定待 v3.0.5+。
3. **级联降级**：选自动 clamp（等比收紧 + 审计）而非拒绝全局变更，避免全局管理员被锁死。
4. **审计保留策略**：租户段 `auditRetentionDays` 字段已预留（本版未启用清理任务，日志按日滚动文件保留）；v3.0.5 评估按租户清理。
5. **既有三角色按租户复用**：admin/user/readonly 在 users 表带 `tenant` 字段即租户内角色；不带 tenant 的旧配置用户回退 "default" 租户。
