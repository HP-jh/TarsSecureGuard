# TarsSecureGuard v3.2.0 · 连接做到极致 —— AI 软件生态全连接指南

> **定位：AI 时代的路由器。** 一个零依赖单文件网关，左边把你能用到的 AI 软件客户端都接进来，右边把
> 全世界的模型提供商（云端 24 家 + 本地 8 种运行时）都连出去——所有流量过同一套 WAF / RBAC / 审计 / 脱敏安全链。
> 长线愿景：通过 TSG 连接一切可连接的软件。本版本先把架构与覆盖面推到极致。

本文件四部分：**一、Inbound**（13 个 AI 客户端接入指南）；**二、Outbound**（24 云端 provider + 8 本地运行时）；
**三、连接架构**（provider-registry / 连接池 / 熔断 / 缓存 / 自动发现）；**四、管理端点**。
性能基准见 `docs/v3.2.0-performance.md`；暂时无法连接的服务与接入方案见 `docs/v3.2.0-unconnectable.md`。

通用前提：网关默认监听 `http://127.0.0.1:8080`，鉴权用网关密钥（首次启动写入 `gateway-key.txt`，
默认 `tars-gateway-key`，正式使用请改配置）。下文用 `TSG_KEY` 指代该密钥。

## 一、Inbound：让 AI 软件客户端连进来（13 个）

TSG 暴露两种入口，客户端按自身能力二选一：

- **OpenAI 兼容 HTTP API**（推荐）：`http://127.0.0.1:8080/v1/chat/completions`，任何「自定义 OpenAI Base URL」的客户端都能接；
  模型名直接写注册表模型（如 `openai/gpt-4o`、`anthropic/claude-sonnet-4-5`、`deepseek/deepseek-chat`，完整清单见第二部分）。
- **MCP**：HTTP 端点 `http://127.0.0.1:8080/mcp`（POST JSON-RPC）或 `tsg --mcp-stdio` 走标准 stdio 传输，把网关的
  模型路由 / 搜索 / 工具能力暴露为 MCP tools。

### 1. Claude Desktop（MCP stdio）

`claude_desktop_config.json`（macOS: `~/Library/Application Support/Claude/`；Windows: `%APPDATA%\Claude\`）：

```json
{
  "mcpServers": {
    "tars-secure-guard": {
      "command": "/path/to/tsg",
      "args": ["--mcp-stdio"]
    }
  }
}
```

重启 Claude Desktop 后即可在对话中调用网关内置工具（模型路由、搜索、WAF 审计查询）。

### 2. Cursor（OpenAI 兼容）

- API Key: `TSG_KEY`
- 模型：添加 `openai/gpt-4o`、`anthropic/claude-sonnet-4-5`、`deepseek/deepseek-chat` 等（模型名与 `/v1/models` 返回一致）

### 13. Zed（自定义 OpenAI provider）

`~/.config/zed/settings.json`：

```json

      "api_url": "http://127.0.0.1:8080/v1",
```

## 三、连接架构（为「连接一切」打底）

### provider-registry：新增 provider 只写配置，不改核心

- 每个 provider 一个 `providers/<id>.json`（go:embed 编译进二进制，32 份档案随发版走）；
- 运行时覆盖走 config.json `providers.<id>`（apiKey / baseUrl / enabled / models）或环境变量；
- 启动 fail-fast：云端注册项 <20 个视为打包损坏，拒绝启动；
- 路由三级命中：`providerId/model` 显式前缀 → 裸模型名反查注册表 → v3.0.x legacy cloud 配置兜底；
- 密钥红线：注册表文件静态扫描禁止 `apiKey`/`sk-` 等字样（有测试兜底）；管理端点只输出 `keySet` 布尔，永不回显密钥。

### 共享连接池（pool.go）

全进程单个 `http.Transport`（MaxIdleConns=256 / PerHost=32 / HTTP2 / TLS1.2+），
经 `trackedTransport` 用 httptrace 实测连接新建/复用计数——复用率是实测值而非估算。

### 健康探测 + 熔断器（circuit.go）

closed →（连续 5 次失败）→ open（30s 冷却，出站直接拒绝）→ half-open（放 1 个探测）→ 恢复/再熔断。
状态迁移全部落审计（PROVIDER_CIRCUIT_OPEN / RECOVER）。后台 worker 只探测「已配密钥且非 closed」的云端 provider。
**熔断只影响路由可用性，永不绕过安全链。**

### 两级缓存（adapters.go）

① 协议适配缓存：messages → 目标协议请求体，按内容哈希 LRU（128 条）；
② 响应缓存：完整请求 → 响应文本（默认 300s TTL / 1024 条 LRU），**key 含租户标识，跨租户永不命中**；
配置热重载全量失效。缓存命中的内容必然已通过 WAF / 语义分级 / 脱敏（安全链在缓存之前）。

### 协议适配器

openai-compat / anthropic（system 提升至顶层字段）/ gemini（role=model + systemInstruction）/ ollama 原生，四选一自动按 provider 配置生效。

### 自动发现（既有 autoDiscovery 模块）

网关每 60 秒扫描本地运行时（Ollama / LM Studio 等），发现的模型自动并入 `/v1/models` 与管理面板。

## 四、管理端点（v3.2.0 新增）

| 端点 | 方法 | RBAC | 用途 |
|---|---|---|---|
| `/api/admin/v32/providers` | GET | admin.read | 注册表全景（keySet/circuit/ready） |
| `/api/admin/v32/providers/probe` | POST | admin.write | 主动健康探测（可 `?id=openai` 单家） |
| `/api/admin/v32/pool` | GET | admin.read | 连接池复用率指标 |
| `/api/admin/v32/cache` | GET | admin.read | 两级缓存命中率 |

## 五、升级与兼容

- v3.0.x 全部行为保留：`lmstudio/`、`ollama/` 前缀路由、legacy cloud 配置、MCP、多租户、观测层；
- v3.2.0 新增均为加法，未触碰 Tier 0-3 安全架构（WAF / 语义分级 / RBAC / 脱敏 / 硬黑名单零改动）；
- config.json 热重载对 `providers` 段生效（2 秒轮询），改密钥不用重启。
