# TarsSecureGuard v3.2.3 性能升级 v2 报告

> 路线图定位：v3.2.3 = 性能升级 v2（深度性能优化）。
> 上版基线：v3.2.2 性能升级 v1（`docs/v3.2.2-performance.md`：审计日志单行 -79%、
> 连接池覆盖补全、tier1 正则包级化）。本轮从 v3.2.2 报告第五节的候选方向出发，
> 逐项勘察后**实做三项、排除两项、证伪一项**，全部零安全削弱、纯标准库。

## 一、候选方向逐项定夺（先勘察后动手）

| 候选 | 定夺 | 理由 |
|---|---|---|
| WAF 多正则单遍合并 | **实做** | 每请求正文要过全部规则正则（strict 6 条），逐条全串扫描是文本路径最大头 |
| PII 脱敏单遍化 | **实做** | 四条模式四次 ReplaceAll 全串扫描，可合并为一次 |
| 响应缓存分片锁 | **实做** | 全局 respMu 在高并发下串行化 get/put |
| 请求体 JSON sync.Pool | **排除** | 勘察发现 marshal 位点多在 adaptCache 之后或冷路径，收益边际，不值得引入池复杂度 |
| auditV2Write 批量 group commit | **排除** | auditV2Mu 持锁贯穿全天切换 + hash 链 + 写文件，**写入序即 hash 链序**；改异步/批量引入丢行与断链风险，不值得 |
| SSE 流式 buffer 复用 | **证伪** | grep 全仓仅见 `"stream": false`——代码中**不存在 SSE 流式路径**，候选不成立 |

## 二、改造内容

### 1. WAF 合并正则 + ASCII 触发字节预筛（`waf.go`）

- normal 与 strict 规则各预编译为**一条 alternation 合并正则**（`(?:r1)|(?:r2)|...`，包级一次编译），单遍快筛替代逐规则多次全串扫描；快筛命中后按原顺序回查个别规则取回命中名，**返回值与逐条实现完全一致**（12 用例等价性测试锁定，含「normal 模式不检 SQLi」等模式语义）；
- 新增 `wafNeedsScan` 预筛：六条规则的全部命中前提是正文含 ASCII 触发字节（字母/数字/`.`/`%`/`;`/`&`/反引号/`<`/`=`/`:`/`@`/`/`/`*`/`(`/`)`）——逐条核验过每条规则的文法依赖。纯中文正文（UTF-8 字节 ≥0x80）不含触发字节 → **整串免正则直接判无命中**。中文聊天是本网关的主要负载形态，这是本轮最大收益来源；
- 规则表 `wafRules` 一行未动，strict/normal 分级语义不变。

### 2. PII 脱敏单遍化（`waf.go`）

- 四条 PII 模式（卡号/SSN/邮箱/手机号）合并为一条正则，`maskPII` 从四次全串 ReplaceAll 降为一次；
- 四模式文法互斥（卡号需 16 数字、SSN 需 `ddd-dd-dddd`、邮箱需 `@`、手机号需 11 数字且非 4 的倍数分组），单遍替换与逐条替换结果一致（8 用例等价性测试锁定）。

### 3. 响应缓存 16 分片锁（`adapters.go`）

- 全局 `respMu/respCache/respLRU` 拆为 16 个分片，每片独立 mutex + LRU + 命中/未命中计数；key 经 FNV-1a（只扫前 8 字节 + 长度，生产 key 为 64 hex sha256，分布充分）定位分片；
- 语义变化（已注释声明）：容量按片均分（`(max+15)/16`），LRU 片内淘汰，**总条数 ≤ max 硬约束不变**；tenant 仍参与缓存键，v32CacheInvalidate 遍历清全部 16 片；
- `cacheStats` 聚合 16 片计数并新增 `shards` 字段。

## 三、基准数据（同机对照，`-benchtime 200x -count 3` 取中位数）

**WAF wafMatch 与 PII maskPII（正文 ~1.2KB 中文主导，A=改造前逐条，B=合并+预筛）**：

| 负载 | A（改造前） | B（改造后） | 变化 |
|---|---|---|---|
| WAF normal（中文正文+URL 参数） | 68 µs | 65.4 µs | -4% |
| WAF strict（中文正文+英文尾巴） | 433 µs | 369 µs | **-15%** |
| WAF strict（**纯中文正文**） | ~474 µs（对照†） | **0.99 µs** | **-99.8%** |
| PII maskPII（中文正文+完整 PII 样本） | 97 µs | 81 µs | **-15%** |

† 纯中文无预筛对照（合并正则、关闭预筛临时实测）：474 µs；改造前逐条正则对同长度纯中文正文为同量级（A 侧 strict 基线 433µs 输入同为中文主导正文）。

**响应缓存 get/put（256 键随机读写，RunParallel 并发）**：

| 实现 | ns/op | 变化 |
|---|---|---|
| A：全局单锁 | 206 ns | — |
| B：16 分片锁 | 186 ns | **-10%** |

> 环境声明：沙箱 2C4G / linux-amd64 / Go 1.22.8；绝对值偏乐观，但 A/B 同机同负载，
> **相对差距可信**。分片锁收益随并发与核数放大（本沙箱仅 2 核）。

## 四、安全不妥协声明

- WAF/PII 合并与预筛**不改变任何命中语义**：合并正则命中后仍按原顺序回查取命中规则名，20 个等价性用例（WAF 12 + PII 8）锁定行为；
- 预筛的免扫描判据（无 ASCII 触发字节 → 必无命中）由六条规则的文法逐条核验支撑，并受等价性测试覆盖（含纯中文用例）；
- 缓存分片只改锁粒度：总容量上限、TTL、tenant 隔离、失效广播逻辑不变；
- 全量 **136 个测试**（+3：WAF 等价性 / PII 等价性 / 分片缓存行为与并发）在 `-race` 下通过（5.3s）。
