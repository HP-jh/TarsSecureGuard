# TarsSecureGuard v3.2.2 性能升级 v1 报告

> 路线图定位：v3.2.2 = 性能升级 v1（连接池 / circuit breaker / 缓存的深化与覆盖补全）。
> 事实基线：连接池、每 provider 三态熔断器、响应缓存在 **v3.2.0 已交付**（含基准报告
> `docs/v3.2.0-performance.md`：出站 P99 -40%/-27%、复用率 98.5%、缓存命中 42.5%）。
> 本轮工作 = 补全 v3.2.0 之后的**真实剩余瓶颈**，全部改动零安全削弱、纯标准库。

## 一、瓶颈定位（本轮实测发现，按影响排序）

| # | 瓶颈 | 位置 | 影响 |
|---|------|------|------|
| 1 | **日志落盘每行 open→write→close**（全局互斥） | `logging.go fileLog` | 一次带审计的请求触发 2 次 fileLog（audit+tars）+ 1 次 auditV2Write；旧行为 = 每请求额外 4 个 syscall（2 open + 2 close）+ 路径拼接/日期格式化，且文件操作串行化在全局锁内 |
| 2 | doctor 探测 / 自定义工具路径旁路连接池 | `doctor.go`×2、`customtools.go` | 诊断路径每次探测新建 Transport（无连接复用）；web fetch 工具 Transport 用默认参数（MaxIdleConnsPerHost=2），同站连续抓取频繁关连接重建 |
| 3 | 硬件探测逐调用编译正则 | `tier1.go`×3 | 每次 CLIXML/lspci/plist 解析都 `regexp.MustCompile`（冷路径，属工程卫生） |

## 二、改造内容

### 1. 日志常开句柄管线（`logging.go` 重写）

- 每个前缀（tars / waf / audit）**常开一个句柄**，写入只剩 1 次 write syscall；
- 跨天首写自动轮转：关闭昨日句柄、打开新日期文件（轮转语义与旧实现一致）；
- 句柄写失败即关闭丢弃、下一行重试打开（失败静默，不影响主流程——语义不变）；
- 写入仍同步（不引入异步丢行风险）；新增 `closeLogFileHandles()` 供优雅退出。
- 日期函数可注入（`logDayFunc`），轮转可测。

### 2. 连接池覆盖补全（`pool.go` / `doctor.go` / `customtools.go`）

- 新增 `pooledHTTPClient(timeout)`：任意超时的客户端都挂共享 Transport（复用空闲连接），doctor 两处探测接入；
- oauth.go / circuit.go 在 v3.2.2 治理层实施时已接池（`httpClientShort` / `sharedTransport`），本轮确认无回归；
- **customToolClient（web fetch 工具）**：SSRF 拨号校验 Transport 必须与主池隔离（安全不变量），但对齐主池连接复用参数（MaxIdleConns 64 / PerHost 8 / IdleConnTimeout 90s / TLS 握手 10s / HTTP2）。

### 3. tier1 正则提升为包级预编译（行为不变，`tier1.go`）

## 三、基准数据（同机对照，`go test -bench -count 3` 取中位数）

**审计日志单行落盘延迟（A/B：旧 open-per-line vs 新常开句柄，同目录同负载）**：

| 实现 | ns/op（3 轮） | 中位数 |
|---|---|---|
| 旧：每行 open+write+close | 3963 / 4161 / 4004 | **4004 ns** |
| 新：常开句柄 | 832 / 830 / 861 | **832 ns** |

**单行 -79%**。带审计的请求路径每次省约 2×3.2µs ≈ **6.3µs**（两次 fileLog），
叠加路径拼接与日期格式化的消除；高并发下全局锁持有时间同步缩短（锁内不再有 open/close）。

**连接复用**：`TestV322PooledHTTPClientReuse` 用 httptrace 实测同 host 第二次请求命中空闲连接；
customtools 调优后同站连续抓取不再受默认 PerHost=2 限制。

> 环境声明：沙箱 2C4G / linux-amd64 / Go 1.22.8，本机 tmpfs 上落盘；绝对值偏乐观，
> 但 A/B 同目录同负载，**相对差距可信**。

## 四、安全不妥协声明

- fileLog 只改「怎么写文件」，不改「写什么、何时写」：审计事件仍在请求路径同步落盘（hash 链 auditV2Write 逻辑一行未动）；
- customToolClient 的 SSRF 拨号校验（实际 IP 私网段拒绝）、禁重定向、与主池的隔离**全部保留**，只调连接参数；
- doctor 池化只影响其自身的出站连接复用，探测判定逻辑不变；
- 全量 **133 个测试**（+7：句柄常开/跨天轮转/并发无丢失/池化共享与复用/customtools 参数与 SSRF 保留/tier1 行为不变/A-B 基准）在 `-race` 下通过。

## 五、v3.2.3（性能升级 v2）候选方向

请求体 JSON 复用 marshal 缓冲（sync.Pool）、WAF 多正则扫描的单遍合并、响应缓存的分片锁、
auditV2Write 批量 group commit（保序前提下）、SSE 流式路径的 buffer 复用。届时以实测瓶颈为准取舍。
