## 🏗️ 新增架构：Pipeline 管道引擎

### 设计理念

参考三大顶级架构：
- **腾讯 NT 架构**：消息管道的 Stage 模式，每个阶段职责单一、可组合
- **字节双线程模型**：UI/Logic 安全边界隔离，RequestContext 贯穿管道
- **阿里巴巴编译器**：IR Pass 管道（每 pass 独立、可组合、可观测、带 panic recovery）

### 核心组件

```
Pipeline（管道引擎）
├── Stage 接口          — 处理阶段的标准协议
├── StageFunc 适配器    — 函数式阶段快捷创建
├── RequestContext      — 贯穿管道的请求上下文
├── StageMetric         — 每阶段执行指标（耗时、结果、错误）
├── Observer 接口       — 观测回调（Prometheus / 审计 / Trace）
└── Bridge 桥接器       — 新旧架构渐进式迁移
    ├── ModeShadow      — 影子模式（只观测不干预）
    ├── ModeGradual     — 渐进模式（已迁移阶段走 Pipeline）
    └── ModeFull        — 完全模式（Pipeline 接管一切）
```

### 标准安全阶段

| Stage | 对应原代码 | 说明 |
|-------|-----------|------|
| `IPBanCheckStage` | `isBanned(clientIP(r))` | IP 封禁检测 |
| `WAFCheckStage` | `wafCheck(r)` | WAF 规则匹配 |
| `CORSPreflightStage` | CORS OPTIONS 处理 | 跨域预检 |
| `AuthStage` | `identityFromRequest(r)` | 身份认证 |
| `RBACCheckStage` | `rbacCheck(id, method, path)` | 角色权限检查 |
| `QuotaCheckStage` | `quotaCheck(tenant, user, groups)` | 配额检查 |
| `RateLimitStage` | `rateLimitMiddleware(...)` | 三维令牌桶限流 |
| `MetricsStage` | `mu.Lock(); totalReq++` | 请求计数 |

### 迁移路径（4 阶段）

```
Phase 1 ✅ 影子模式验证
  → Pipeline 与 gatewayMiddleware 并行执行
  → 对比判定结果，确认一致性

Phase 2 ⏳ 渐进式迁移
  → 逐个阶段从 gatewayMiddleware 迁到 Pipeline
  → 已迁移阶段由 Pipeline 处理，其余走旧代码

Phase 3 ⏳ 完全接管
  → gatewayMiddleware 退化为 Pipeline.Execute 调用
  → 旧中间件代码标记废弃

Phase 4 ⏳ 清理
  → 删除 gatewayMiddleware
  → Pipeline 成为唯一入口
```

## 🔒 安全不变量

本次重构**严格遵守**以下安全守则（来自 HP-jh 编写的核心文件和安全规范）：

1. **Security Core 不可关闭** — Pipeline 中安全阶段没有跳过开关
2. **AI 只能加严** — Pipeline 的 StageResult 只支持 Continue/Halt/Skip，不支持"降级"
3. **Fail-close 铁律** — 任何阶段 panic 时默认 Halt（拦截），绝不放行
4. **SSRF 五红线** — 不受本次重构影响，`ssrfGuardedClient` 保持不变
5. **Hash-chain 审计** — Pipeline 的 Observer 接口可直接对接审计系统
6. **零依赖** — 所有新代码仅使用 Go 标准库，`go.mod` 零第三方依赖不变
