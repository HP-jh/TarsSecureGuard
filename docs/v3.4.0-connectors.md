# TarsSecureGuard v3.4.0 连接器生态与工具链路降耗

对应 11 项纵深路线图中的：**项 1（强化连接能力：连接器生态）+ 项 2（优化工具调用链路：压缩中间环节、减少冗余 Token 消耗、内置轻量级 Token 测量器）**。

## 一、连接器生态（项 1）

内置模板目录 + 用户实例两层模型，AI 经 `conn_<template>` 工具无缝接入外部平台与数据源：

- **内置模板（8 个，编译进二进制）**：
  - `github_repo` / `github_issues`：GitHub 仓库与 Issues（Token 走 `env:GITHUB_TOKEN`，不落盘）
  - `webhook_notify`：Webhook 通知（POST，自定义 url）
  - `wikipedia_search`：维基百科搜索
  - `weather`：实时天气（Open-Meteo，免 Key）
  - `ip_info`：IP 归属查询
  - `hn_top` / `hn_item`：Hacker News 热榜与条目
- **实例化启用**：`POST /api/admin/v34/connectors`（template/name/params/enabled），必填参数校验后写入 `config.json` `v34.connectors`（2 秒热重载）；实例参数优先于模板默认值
- **参数展开优先级**：调用参数 > 实例 params > 模板 Default；必填缺失直接报错（不猜测）
- **密钥不落盘**：headers 值支持 `env:VAR` 形式，运行时从环境变量读取（如 `Authorization: env:GITHUB_TOKEN`）
- **执行层复用既有安全通路**：连接器与自定义工具共享 `executeForwardedRequest` 公共转发层——SSRF 五红线（拨号时实际 IP 校验防 DNS 重绑定 / 禁重定向 / 协议白名单 http/https / 30s 超时 / 2MB 响应上限）一处落实、两侧同构，杜绝安全面漂移
- **工具链路打通**：`conn_*` 工具进入 executeTool 分发链（内置 tools → customTools → conn_*）与 `/api/tools` 列表；沿用守门人策略门与审计（`CONNECTOR_CALL` / `CONNECTOR_CONFIG`）
- **模块化**：新增 `connectors` 模块（依赖 builtinTools，默认开启），关停后连接器路由与 conn_* 工具随模块开关热生效

## 二、Token 测量器（项 2：实时成本反馈）

- **埋点**：`routeChatEx` 命名返回值 + defer 统一出口埋点，一处覆盖所有后端路径（本地 / LM Studio / Ollama / 云端 / custom），成功与失败调用都记账
- **记录**：进程内环形缓冲 2000 条 + 按天聚合（保留 8 天）+ 按模型聚合；不持久化、不落盘，重启清零
- **定价三层**（与能力库同构）：`config.json` `v34.pricing.overrides`（`provider/model` 或 `model` 键）> `providers/*.json` `modelPricing`（精确模型）> `pricing`（provider 默认），单位 USD / 1M tokens
- **诚实计价**：本地后端（llama / lmstudio / ollama）免费；未登记定价的云端模型只记 tokens 不计金额（`priced:false`，前端标「免费」/「未定价」），不编造价格
- **内置定价**：23 个云端 provider 登记 `pricing` 与常用模型 `modelPricing`（如 openai 2.50/10.00、gpt-4o-mini 0.15/0.60；deepseek 0.27/1.10、deepseek-reasoner 0.55/2.19；智谱 glm-4-flash 0/0 免费）；以各平台公开定价页为准，可经 overrides 校正
- **API**：
  - `GET /api/admin/v34/meter`：today/total/byDay/byModel（按 tokens top20）/recent（50 条）/slimSaved/slimCalls/module
  - `POST /api/admin/v34/meter`：清零（审计 `METER_RESET`）
  - `POST /api/v34/meter/estimate`：`{text, model?}`——字符/4 估算 tokens；带模型返回单次调用预估成本，不带返回有定价模型的成本对比（升序 top10）
- **模块化**：新增 `tokenMeter` 模块（依赖 chatApi，默认开启），关停后测量路由 503

## 三、工具调用链路降耗（项 2：压缩冗余 Token）

- **tools schema 瘦身**：出站请求体的 tools schema 经 `slimToolsSchema` 递归压缩——剔除 `strict:false`、`additionalProperties:false` 与空容器（`[]` / `{}` / `""`），仅保留有语义的 `strict:true` 等字段；瘦身反而变大则原样返回（绝不负优化）
- **收益可观测**：累计节省 tokens（`slimSaved`）与瘦身次数（`slimCalls`）进测量器 API 与前端总览；apply 阶段瘦身、响应链路零侵入（工具语义不变）

## 四、前端

- 新增「Token Meter」页：成本总览 stats-grid（今日调用/tokens/成本、累计、瘦身节省）、在线估算器（文本 + 可选模型 → 单次成本 / 模型成本对比）、按模型汇总表（tokens/成本/错误率）、最近调用明细表
- 新增「Connectors」页：模板目录卡片（分类 / 文档链接 / 免 Key 标记）、实例配置表单（模板选择 + JSON 参数 + 启用/禁用）
- 版本徽章更新 v3.4.0；沿用既有设计令牌（.tag on/off/loc、stats-grid、api()/esc()），单文件 embed 惯例不变
