## Раунд 4 — Payload, улучшенные с помощью LLM (Agnes AI flash + ручное сопровождение)

При первом успешном вызове LLM получил 5 обычных payload; позже из-за ограничения скорости запросов (ошибки 429/403) был переключён на режим совместной работы "LLM генерирует ключевые идеи, человек конструирует полезную нагрузку под конкретную задачу":

| Payload | Техника | Результат для WAF синей |
|---|---|---|
| `UNION ALL SELECT NULL` | Вывод LLM | **Обход WAF с кодом 401** (\bunion\s+select\b не совпадает с UNION ALL SELECT) |
| `1 /*!50000UNION*/ /*!50000SELECT*/ NULL` | Встроенные комментарии MySQL | **Обход WAF с кодом 401** |
| `1%2520UNION%2520SELECT%2520NULL` | Двойное URL-кодирование | **Обход WAF с кодом 401** |
| `1&id=1 UNION SELECT NULL` | Загрязнение параметров HPP | Заблокировано с кодом 403 |
| `1 UNION SELECT 0x68656c6c6f` | Шестнадцатеричная строка | Заблокировано с кодом 403 |
| `1 UNION SELECT CASE WHEN(1=1) THEN 1 END` | Конструкция CASE WHEN | Заблокировано с кодом 403 |

**Основной вывод №4 (важнейшее открытие)**: Регулярное выражение для sqli синей команды использует `\bunion\s+select\b`, которое требует **непосредственного соседства** UNION и SELECT. Встроенные комментарии MySQL (`/*!...*/`), добавление ALL между операторами и двойное URL-кодирование позволяют разделить UNION и SELECT → обход защиты в 3 из 6 случаев. В производственной среде WAF должен уметь парсить комментарии и кодировку, сопоставляя все эквивалентные формы, иначе блокировка не работает.

**Урок рабочего процесса Раунда 4**: Квота LLM истощается мгновенно, в реальной производственной среде ИИ-ассистент работает как **генератор идей**, а не **автоматический инструмент для атак** — более надёжный подход: "LLM даёт направление, человек проводит глубокую конструкторскую работу под конкретную задачу".

## Раунд 5 — Комплексная атака и защита + недостатки эшелонированной защиты

| Вектор | Синяя | Красная |
|---|---|---|
| Обход пути (3 варианта) | Заблокировано 3/3 | Заблокировано 3/3 |
| XSS `<script>` | Заблокировано с кодом 403 | Заблокировано с кодом 403 |
| XSS `javascript:` | Заблокировано с кодом 403 | Заблокировано с кодом 403 |
| XSS `<img src=x onerror=>` | Заблокировано с кодом 403 | **Пропущено с кодом 404** (не совпадает с правилами WAF) |
| cmd `;id` / `\|ls` / `` `id` `` / `&whoami` | 404 (не совпадает с правилами WAF, но обработчик hello не принимает cmd параметры) | **Пропущено с кодом 401** (не совпадает с правилами WAF) |
| Полный набор чёрного списка UA | Блокировка `sqlmap/nmap/masscan`, пропуск `Mozilla/5.0 sqlmap` | **Все пропускаются** |

**Основной вывод №5 (XSS-уязвимость красной команды)**: Правило для xss красной команды написано как `<script|javascript:|onerror=`, где `onerror=` проверяется по **точному совпадению строки**, но в конструкции `<img src=x onerror=alert(1)>` после onerror= следует `alert`, а не допустимое событие. Вместо точного сравнения строк нужно использовать регулярное выражение `onerror\s*=` без учёта регистра. Покрытие неполное.

**Основной вывод №6 (Не работающее правило cmd_injection у красной команды)**: Правило cmd_injection красной команды включает 4 символа: `;|\||\`|\&`, но в URL `;` является разделителем параметров, а `|` и `&` — операторами оболочки. Эти символы по отдельности **являются допустимыми символами URL**. Использование сопоставления по отдельным символам в WAF → высокий уровень ложных срабатываний → возможно **случайное отключение правила** при его редактировании. При проверке все 4 payload вернули код 401 (обошли WAF), у синей команды все 4 также вернули 404 (также обошли WAF) — **у обеих команд правила cmd_injection фактически не работают**, это не проявилось только потому, что `/api/hello` не принимает параметры cmd.

## Итоговая оценка: ключевые выводы по безопасности (применимы в производственной среде)

1. **Учётные данные = ключ**: WAF не может заблокировать легитимный доступ по "валидным учётным данным + допустимому пути". В производственной среде для интерфейсов доступа к секретам обязательно нужен **дополнительный уровень защиты** (белый список IP, mTLS, динамические токены, ограничение частоты запросов).
2. **WAF не должен использовать точное сопоставление строк для сигнатур атак**: Пропуск `Mozilla/5.0 sqlmap`, пропуск `<img onerror=>`, пропуск UNION с комментариями между операторами — все это случаи "видимость блокировки при её фактическом отсутствии".
3. **В WAF обязательно должен быть модуль header_anomaly**: У красной команды в 4 классах правил **отсутствует чёрный список UA** — любой отпечаток инструмента проходит через защиту, достаточно подделать UA.
4. **Правила cmd_injection по отдельным символам — это ловушка**: Неправильно написанное правило не работает вообще. Нужно использовать сопоставление по шаблонам с учётом контекста (за командой следуют названия функций `id`, `whoami`, `cat`).
5. **LLM — это помощник, а не замена специалиста**: Flash-модель отработала успешно при первом запуске, позже получил ошибки ограничения скорости 429/403 — в производственной среде обязательно нужна совместная работа "ИИ + человек", нельзя полностью полагаться на атаки с помощью LLM.
6. **Одинаковый код — одинаковые уязвимости**: Базовый код WAF обоих сервисов почти идентичен — это значит, что у обеих сторон есть одинаковые пропуски защиты, отличаются только условия их срабатывания. В реальной экосистеме это приводит к "копированию уязвимостей в 41 месте".
