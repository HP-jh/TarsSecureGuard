# TarsSecureGuard v3.2.2 治理层设计文档

> 六大模块：共享记忆 / 共享信息 / 上下文拓展 MCP / OAuth·IdP / 守门人 / 审计升级。
> 全部 Go 标准库实现，零第三方依赖；对应代码 `sharedmemory.go` `sharedinfo.go` `contextmcp.go` `oauth.go` `oauth-jwt.go` `gatekeeper.go` `auditv2.go`，测试 `v322_test.go`（全量 126 条 -race 绿）。

## 0. 设计总纲

v3.2.0 解决「连得多」，v3.2.1 解决「开箱即用」，v3.2.2 解决「**管得住**」：多用户 / 多租户场景下，谁记得什么、谁看到什么、谁被允许做什么、事后能不能查清。

三条贯穿原则：

1. **安全链无旁路**——所有新能力要么挂在既有安全链之内（上下文注入发生在 PII 脱敏之前），要么本身成为安全链的新环节（守门人、审计 v2）。
2. **零依赖不变**——不为了治理功能引入任何第三方库，包括 JWT 验签（手写标准库实现，密码学代码集中在 `oauth-jwt.go` 一处便于审计）。
3. **收紧-only**——运行期配置只能让默认策略更严，不能更松；尝试放宽即拒绝并留痕。

## 1. 共享记忆（shared-memory.go）

**问题**：同一用户 / 租户跨会话需要记住偏好与状态（如「回复用中文」「生产环境只监听 127.0.0.1」），但散落在各家客户端本地不可治理。

**设计**：

- **三层命名空间**：`user:<tenant>/<user>`（个人层）→ `tenant:<tenant>`（租户层）→ `global`（全局层）。读取走**就近覆盖解析链**：个人层命中即返回，否则租户层，否则全局层——同一 key 可以在不同层级被覆盖，解析结果确定。
- **租户隔离靠规范化而非靠校验**：`smNormalizeNS` 把调用方传的 "tenant" 无条件落到**自己租户**的 ns。调用方无论怎么传 ns 字符串，都不可能构造出他租户的命名空间——隔离是结构性的，不依赖每个读写点都记得做权限检查。
- **配额与驱逐**：每 ns 1000 条、单值 64KB、全局 10000 条；超限 LRU 驱逐最旧条目；TTL 到期自动失效。落盘 `shared-memory.json`，重启恢复。
- **global 写权限**：仅 `global_admin`（写全局 = 跨租户影响，必须收敛到管理员）。

**REST / 工具**：`/api/context/memory` + `tars_shared_memory_set/get/list/delete`。

## 2. 共享信息（shared-info.go）

**与共享记忆的分工**：记忆是 key-value 的「状态」（语言、阈值、开关），信息是结构化的「知识」（部署规范、决策记录、链接），带类型、标签、置信度、来源。

**设计**：

- 四种类型 `fact / preference / note / link`；可见范围 `tenant / global`（global 写同样仅 `global_admin`）。
- 检索 `siSearch` 按命中权重排序：标题 100 > 标签 80 > 内容 40，同级按更新时间倒序——用户查「部署」，标题命中的条目天然排在正文顺带提一句的前面。
- 上限 5000 条、单条 32KB；落盘 `shared-info.json`。

**REST / 工具**：`/api/context/info` + `tars_shared_info_add/search/delete`。

## 3. 上下文拓展 MCP（contextmcp.go）

**问题**：接入 TSG 的各家 AI 客户端各自维护上下文，安全策略与共享知识无法跟随请求进入模型。

**设计**：

- `buildContextPack` 按**确定顺序**组装三段：`身份与策略`（当前用户、角色、租户、生效的安全策略摘要）→ `共享信息`（按检索相关性）→ `共享记忆`（按命名空间层级）。
- **身份与策略段永不截断**——其余段默认预算 4096 字符，整行截断并标注 `(已截断)`，保证截断点不落在一行中间产生歧义。
- 命名上下文包 `tars_context_pack_save/load`：把组装结果存为可复用命名包（上限 100 个，租户可见性隔离）。
- **聊天注入无旁路**：`/api/chat` 请求体 `context` 字段触发的注入发生在 **PII 脱敏与语义防护之前**——注入文本与用户输入过完全相同的安全链。注入的共享知识若含 prompt 注入特征，会被语义防护拦下。

**REST / 工具**：`/api/context/build` + `tars_context_build` + `tars_context_pack_save/load`。

## 4. OAuth / OIDC（oauth.go + oauth-jwt.go）

**问题**：企业内网已有 IdP（Keycloak / Okta / Entra ID），本地账号体系与之割裂。

**设计**：

- **Authorization Code + PKCE（S256）**：`/oauth/login` 生成一次性 state + code_verifier，302 到 IdP；`/oauth/callback` 换 token、验签、发会话；`/oauth/logout` 注销。
- **fail-close 配置校验**：`oauthReady()` 要求 issuer/client_id/client_secret/redirect_url 全齐且 issuer 为 https（localhost 除外），否则所有 OAuth 端点 503。宁可不可用，不可不安全地用。
- **手写 JWT 验签**（`oauth-jwt.go`，集中便于审计）：
  - 算法白名单 RS256 / ES256，显式拒绝 `none` 与 HS256（防算法混淆攻击）；
  - RS256：从 JWKS 取 n/e，`s^e mod n` 还原 EMSA-PKCS1-v1_5 编码块，`subtle.ConstantTimeCompare` 常数时间比对（防时序侧信道）；
  - ES256：**先做 P-256 曲线点校验再验签**（防无效点攻击），`ecdsa.Verify`；
  - iss（容忍尾斜杠差异）、aud（string / array 双形态）、exp（含 60s 时钟偏移容忍）全检。
- **角色映射受控**：IdP role claim → `oauthMapRole` 映射到 TSG 角色，映射结果必须存在于 rbacMatrix，未知角色**拒发会话**（fail-close，不给默认角色）。
- **会话即本地会话**：`tsg_s_*` 32 字节随机 token，内存态（重启即失效），默认 480 分钟；`identityFromRequest` 识别 `Bearer tsg_s_*` 或 Cookie，之后走**与本地用户完全相同的 RBAC 矩阵、WAF、限流、审计**——OAuth 用户没有任何特权路径。

**状态查询**：`/api/admin/oauth/status`（配置就绪度，不泄露 secret）。

## 5. 守门人（gatekeeper.go）

**定位**：既有防线的分工是 WAF 管输入（请求形态）、语义防护管内容（说什么），守门人管**动作**（这一步操作允不允许执行）——工具执行前的最后一道闸。

**内置规则（不可放宽）**：

| 规则 | 动作 | 理由 |
|------|------|------|
| `tars_config_set` 改 `security.* / oauth.* / tenants.* / gatekeeper.* / audit.*` | deny | 安全关键配置禁止经工具通道（模型可触发的路径）修改 |
| 参数含敏感路径（`id_rsa` / `.env` / `credentials` / `.git/config` / `.aws` / `.kube` 等） | deny | 凭据与密钥文件不可被模型读写 |
| 模型启停、非安全配置写、>1MB 写入 | confirm | 高影响动作需人工二次确认 |

**两阶段确认**：首次调用不执行，返回 `gkConfirmationRequired`（含 60 秒一次性 token，绑定 用户 + 工具 + 参数哈希）；客户端带 `confirm_token` 原样重放才执行。token 一次性、参数不匹配即失效、过期即失效。

**收紧-only**：config `gatekeeper.rules` 自定义规则只允许比内置更严；对内置 deny/confirm 配 allow → 拒绝生效并落 `GATEKEEPER_POLICY_OVERRIDE` 审计。

**身份注入防伪造**：`executeToolAs` 是所有工具执行的统一入口——先**删除**调用方参数里的保留键 `_tsgIdentity`，再注入服务端身份。工具处理器从参数取身份时取到的永远是服务端注入值，伪造无效。同时实施速率限制（20 次/分钟/用户）与 pending 上限（10）。

**覆盖面**：`/api/tools/`（handleToolCall）与 `/mcp`（简单 + JSON-RPC 两条路径）全部经 `executeToolAs`；`--mcp-stdio` 维持其原有独立守卫 + adminKey 体系不变（本地 stdio 无 HTTP 面）。

**状态查询**：`/api/admin/v322/status`。

## 6. 审计升级（auditv2.go）

**问题**：v3.0.x 审计是追加式日志，文件被事后篡改无从发现。

**设计**：

- **hash 链**：每条 JSONL 条目带 `prevHash` 与 `hash = SHA256(prevHash + 规范化 JSON 本条)`；后一条的 prevHash 是前一条的 hash——改任何一行，其后所有行的 hash 全部对不上。
- **按日切文件 + 重启续链**：`audit-YYYY-MM-DD.jsonl`；重启时从最后一行读出 prevHash 与序号继续，链不断。
- **校验端点**：`/api/admin/audit/verify`（仅 global_admin / global_auditor）全链重算，报告总数 / 断链位置。
- **导出端点**：`/api/admin/audit/export` 按租户行级过滤；**跨租户访问尝试本身也被审计**（`AUDIT_CROSS_TENANT_ACCESS`）——审计体系的滥用可追溯。

## 7. 模块化与兼容

- 新功能模块 `contextGov`（category: core，默认开启，依赖 builtinTools）：关闭则 10 个治理工具从工具列表隐藏、`/api/context/*` 三条路由 503。OAuth / 守门人 / 审计 v2 属安全面，**不设开关**（安全不可关闭原则）。
- 版本号 `3.2.2`；既有部署升级 = 替换二进制，config.json 新段（`oauth` / `gatekeeper` / `audit`）全部可选、缺省即默认值。

## 9. 已知限制与后续

- OAuth 会话为单实例内存态：多实例部署需共享会话存储（当前定位单机网关，未引入）。
- 共享记忆 / 信息为原子整体落盘：极大规模下的分片与索引留 v3.2.3 性能优化一并考虑。
- 审计 v2 的 `hash` 链防篡改是检测性的（发现篡改），不是预防性的；如需防删可外接 WORM 存储。
- v3.2.3（性能优化：连接池 / circuit breaker / 缓存深化）与 v3.2.4（UI 升级）按路线图推进。
