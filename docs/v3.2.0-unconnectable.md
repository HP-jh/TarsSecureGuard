# TarsSecureGuard v3.2.0 · 暂时无法连接的服务清单（含接入方案草稿）

> 用途：用户对外沟通的底稿。TSG 的目标是「连接一切可连接的」，以下是截至 2026-10（本文撰写时）
> **连不上或不能标准方式连接**的服务。每条给出状态、行动、预计影响与官方线索。
> 事实核验说明：标注「已核实」的条目依据本版开发期间的实际检索；其余以官方主站为准，
> 欢迎在官方公告后提 issue 更新（注册表架构下，一旦对方开放 API，加一份 `providers/<id>.json` 即完成接入）。

---

## Midjourney
- 状态：无公开 API（已核实：官方 Community Guidelines 声明除个别企业白名单外不提供 API/SDK/webhook，自动访问违反 ToS）
- 行动：用户去谈商务对接（enterprise 白名单）；或改用已连接的图像类 API（FLUX.1 / Recraft / Ideogram / Stability）
- 预计影响：图像生成场景的主要缺口；文本链路不受影响
- 备注：https://www.midjourney.com/ · https://docs.midjourney.com/ ；第三方 Discord 逆向封装不可用于生产（封号 + ToS 风险）

## Cursor（自有模型作为 provider）
- 状态：无公开 LLM chat API（已核实：cursor.com/docs/api 提供 Admin/Analytics/Code Tracking/Cloud Agents 等企业 API，均非把 Cursor 模型当通用 LLM provider 使用）
- 行动：监控 API 公告；当前 Cursor 作为「客户端」已可连入 TSG（见连接指南第 2 条）
- 预计影响：低——Cursor 用户实际消费的是上游模型（Anthropic/OpenAI/自研补全），其中公开模型已全部可经 TSG 路由
- 备注：https://cursor.com/docs/api

## v0（Vercel）
- 状态：有官方 API 但为项目/部署型 Agent API（Projects/Chats/Messages/Deployments），非 OpenAI 兼容 chat 协议（已核实）
- 行动：列入协议适配 backlog——注册表架构下新增 `v0` 协议适配器即可；企业版走 enterprise@v0.dev
- 预计影响：覆盖前端原型生成场景
- 备注：https://v0.dev/（API 文档见官方 docs）

## Bolt.new（StackBlitz）
- 状态：未提供公开自助 API（以官方公告为准，本文撰写时未见公开 chat API 文档）
- 行动：监控 API 公告；用户如为企业客户可直接咨询 StackBlitz 商务
- 预计影响：全栈原型生成场景缺口
- 备注：https://bolt.new/

## Lovable
- 状态：未提供公开自助 API（以官方公告为准）
- 行动：监控 API 公告
- 预计影响：低代码建站场景缺口
- 备注：https://lovable.dev/

## Windsurf（自有模型作为 provider）
- 状态：无公开 LLM provider API（其企业 API 面向团队管理，非模型调用）
- 行动：监控公告；Windsurf 作为「客户端」已可连入 TSG（连接指南第 6 条）
- 预计影响：低——同 Cursor 逻辑，公开上游模型已可路由
- 备注：https://windsurf.com/

## Replika
- 状态：无公开 API（仅 App / Web 产品形态）
- 行动：暂不支持；监控公告
- 预计影响：陪伴类对话场景缺口
- 备注：https://replika.com/

## Character.AI
- 状态：无公开 chat API（早期开发者 API 已关闭；第三方 Convai 提供角色 API 但属另一服务）
- 行动：监控官方公告；角色扮演场景可暂用已连接的通用模型 + 自定义 agent 提示词近似
- 预计影响：角色扮演类体验缺口
- 备注：https://character.ai/ · 第三方参考 https://docs.convai.com/

## Notion AI
- 状态：AI 能力内嵌产品，无独立公开 API（Notion 官方 API 管文档不管 AI 调用）
- 行动：暂不支持；文档问答场景可用「Notion API 导出 + TSG 已连接模型」组合实现
- 预计影响：知识库写作场景需自建桥接
- 备注：https://developers.notion.com/

## GitHub Copilot（模型作为独立 provider）
- 状态：不可作为通用 LLM provider 调用（Copilot 的 API 面向补全建议与企业管理，且需 Copilot 订阅；其底层模型由 GitHub 与厂商协议提供，不对外转售）
- 行动：暂不支持；Copilot 用户可在 IDE 中把「自定义模型」指向 TSG（连接指南第 12 条）
- 预计影响：低——公开上游模型已可路由
- 备注：https://docs.github.com/copilot

## Suno（音乐生成）
- 状态：无官方公开 API（第三方代理封装不稳定且违反 ToS 风险高）
- 行动：监控官方公告；用户如有企业需求可联系 Suno 商务
- 预计影响：音乐生成场景缺口
- 备注：https://suno.com/

## Pika（视频生成）
- 状态：无公开 API（以官方公告为准）
- 行动：监控公告；视频生成可关注已连接厂商的同类能力
- 预计影响：AI 视频场景缺口
- 备注：https://pika.art/ （注：Runway 有官方 API，可按需加入注册表）

## Snapchat My AI / Meta AI（消费级内嵌助手）
- 状态：无公开 API（产品内嵌，无开发者接口）
- 行动：暂不支持
- 预计影响：消费端场景，与网关定位重叠度低
- 备注：https://ai.meta.com/ · https://snapchat.com/

## ChatGPT 网页版（免费网页形态）
- 状态：网页形态无 API，但同厂 OpenAI API 已接入 TSG（`openai/*`）——能力等价，无需连接网页版
- 行动：无需行动
- 预计影响：无
- 备注：https://platform.openai.com/docs

## HuggingChat（免费网页版）
- 状态：网页形态无官方 API；同平台 Hugging Face Inference API 已接入 TSG（`huggingface/*`）
- 行动：无需行动
- 预计影响：无
- 备注：https://huggingface.co/inference-api

## 腾讯元宝（App 形态）
- 状态：元宝 App 无独立 API，但同厂混元开放平台 API 已接入 TSG（`hunyuan/*`）——能力等价
- 行动：无需行动
- 预计影响：无
- 备注：https://cloud.tencent.com/product/hunyuan

## JetBrains AI Assistant / Tabnine 自有补全模型
- 状态：自有补全模型无公开通用 chat API（两家均支持把第三方 OpenAI 兼容端点接入自家产品——即它们是 TSG 的客户端而非 provider）
- 行动：无需行动（已作为客户端接入，见连接指南第 10/11 条）
- 预计影响：无
- 备注：https://plugins.jetbrains.com/ · https://www.tabnine.com/

## 汇总：真正的缺口只有 6 类

图像（Midjourney）、代码 Agent（v0/Bolt/Lovable）、陪伴对话（Replika/Character.AI）、
知识库内嵌（Notion AI）、音乐（Suno）、视频（Pika）。其中 4 类已有官方 API 的替代厂商
（图像/视频/音乐均有开放平台），可按需加入注册表；纯消费级内嵌助手与网关定位重叠度低。
IDE 三家（Cursor/Windsurf/Copilot）与两家补全厂商已经反向接通——**它们不是缺口，是客户端**。
