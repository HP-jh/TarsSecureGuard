# TarsSecureGuard v3.3.0 转换中枢与模型库

对应 11 项纵深路线图中的：**项 3（深化网关转换能力）+ 项 4（模型库与能力匹配）+ 项 5（内置常用 API 获取入口）**。

## 一、custom 协议适配器（项 3：任意后端接入）

用户以 OpenAI 兼容格式请求网关，网关自动完成协议转换与参数映射，任意 HTTP 后端即可接入：

- Provider 注册表（`providers/*.json`）新增 `custom` 协议，声明 `CustomAdapterSpec`：
  - `method` / `path`：上游方法与路径（默认 POST）
  - `headers`：模板化请求头（如 `Authorization: Bearer {{.Key}}`）
  - `body`：请求体模板（map/slice/string 递归展开）
  - `responsePath`：点路径取值（如 `result.answer.text`，支持数组索引 `a.b.0.c`）
- 模板占位符：`{{.Key}}`、`{{.Model}}`、`{{.System}}`、`{{.User}}`、`{{.Prompt}}`、`{{.MessagesJSON}}`、`{{.Trace}}`
- 响应叶子为字符串直取，其它类型 JSON 序列化；未命中路径报错（不猜测）
- 安全不变量：custom 协议同样经过 WAF / PII / 语义分级前置链；tools 请求不进响应缓存（避免 tool_calls 语义丢失）

## 二、多模态适配（项 3：文件上传等多模态）

- 入站：`Message.UnmarshalJSON` 兼容 OpenAI 两种 content 形态——字符串（历史路径零开销）与多模态数组（`text` / `image_url` / `file` 部件，`file` 支持 `data` 与 OpenAI `file_data` 两种内联形态）；文本段合并进 `Content`，附件 URL 收进 `Images`
- 出站按协议重建：openai-compat 展开为 content 数组、anthropic 转 content blocks（data:URL→base64 source，http(s)→url source）、gemini 转 `inline_data` / `file_data` parts
- 纯文本路径字节级不变（回归测试锁定）

## 三、模型能力库与能力感知路由（项 4）

- 能力标签：`vision` / `tools` / `longContext` / `json` / `reasoning`
- 三层数据，优先级 **override > registry > inferred**：
  1. override：`config.json` `v33.modelCaps`（用户覆盖层，API 可写）
  2. registry：`providers/*.json` 的 `modelCaps`（精确模型）与 `defaultCaps`（继承）
  3. inferred：模型名模式启发式自动推断
- 能力感知改道：请求带图 / 带 tools / 超 32k 输入时，若目标模型缺能力 → 自动改道到已就绪的具备能力模型（同 provider 优先），落审计 `CAP_REROUTE`；无候选放行原模型（`CAP_REROUTE_SKIP`）
- API：`GET/POST /api/admin/v33/capabilities`（矩阵查询 / override 写入 / autoReroute 开关）
- 前端新增「能力库」页面：能力总览统计、模型 × 能力矩阵（可过滤）、override 编辑、自动改道开关

## 四、API 申请直达（项 5）

- 31 个 provider 注册表中 24 个云端平台补 `applyUrl` 字段（OpenAI / Anthropic / Gemini / DeepSeek / 通义千问 / Kimi / 智谱 / 豆包 / Minimax / xAI / Groq / Mistral / Cohere / Perplexity / Together / Fireworks / OpenRouter / 硅基流动 / 文心 / 混元 / 讯飞星火 / 302.AI / Cerebras / HuggingFace）
- `/api/admin/v32/providers` 响应新增 `applyUrl`；前端「能力库」页 API 直达卡片一键跳转各平台控制台申请 Key
- 注：链接为各平台公开控制台地址，以平台实际为准；本地运行时（ollama / vllm / lmstudio 等 7 个）无需 Key、无此字段

## 五、其余增强

- `/v1/chat/completions`：透传 `tools` / `tool_choice`（openai-compat 协议），回传 `tool_calls` 与真实 `finish_reason`；usage 采用后端真实值（缺失时按字符估算补齐）并计入租户配额；发生能力改道时响应携带 `rerouted` 标注
- 模块化：新增 `capabilityHub` 模块（依赖 chatApi，默认开启），能力库路由与改道行为随模块开关热生效（2 秒热重载）
