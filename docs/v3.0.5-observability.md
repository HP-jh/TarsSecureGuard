> 对应任务：自主迭代第 2 轮（六轮计划）。四项交付：Prometheus /metrics、分布式 trace_id 全链路、`tsg doctor` 自诊断 CLI、Grafana dashboard JSON 模板。
> 铁律遵守：**纯观测不改主流程**（obsMiddleware 包裹在 gatewayMiddleware 之外，判定链零改动；路由/后端调用函数用可变参数 trace 透传，既有调用点全部原样编译）；token / api key 全链路脱敏；trace_id 与现有审计行关联但**不新增持久化存储**；交付云盘不推 GitHub。

## 一、Prometheus /metrics 端点

- 路径 `GET /metrics`，Prometheus 文本格式 v0.0.4（手写渲染，仍零第三方依赖）。
- 鉴权：沿用网关统一 X-API-Key 鉴权；端点归 `app` 类（全角色可读，含 readonly）——Prometheus 抓取器只需一把低权限 key。无 key 返回 401。
- 指标清单（15 个指标族）：

| 指标 | 类型 | 标签 | 说明 |
|---|---|---|---|
| `tsg_http_requests_total` | counter | class, method, code | QPS（按 class 求速率） |
| `tsg_http_request_duration_ms` | histogram | class | 延迟 p50/p95/p99（桶 1ms..30000ms） |
| `tsg_waf_hits_total` | counter | rule | WAF 命中（按规则名） |
| `tsg_router_decisions_total` | counter | backend, result | 模型路由分布（成功/失败） |
| `tsg_router_explore_total` | counter | — | ε-greedy 探索次数 |
| `tsg_router_backend_duration_ms` | histogram | backend | 各后端耗时 |
| `tsg_guard_tier` | gauge | — | 资源守卫层级 L0-L3 |
| `tsg_guard_rss_mb` | gauge | — | 进程 RSS（MB） |
| `tsg_module_up` | gauge | module | 模块状态（1=启用） |
| `tsg_backend_up` | gauge | backend | 后端可达性（15s 缓存探测） |
| `tsg_quota_used_today` | gauge | tenant | 租户日配额用量 |
| `tsg_uptime_seconds` | gauge | — | 运行时长 |
| `tsg_build_info` | gauge | version, goos, goarch | 构建信息（恒为 1） |
| `tsg_active_traces` | gauge | — | 进行中 trace 数 |
| `tsg_traces_total` | counter | — | 累计 trace 数 |

- **脱敏保证**：标签只取低基数枚举（class/method/code/rule/backend/module/tenant），绝不出现 user/token/key；span 详情经 `obsRedact` 二次兜底（bearer / sk- / key= / token= / secret= / password= 前缀及 ≥32 位十六进制串一律 `***`）。单测覆盖 + 真进程冒烟对 /metrics 全文做密钥泄露扫描（无泄漏）。

## 二、分布式 trace_id 全链路

- obsMiddleware 在最外层生成 16-hex trace_id（crypto/rand），写入 `context` 并回写响应头 `X-Trace-Id`——客户端拿到响应头即可在日志里反查这次请求。
- 贯穿链路：`生成 → WAF → RBAC/配额 → 路由 → backend`：
  - 网关内部各阶段经 `obsStage` 记 span（request / waf / auth / rbac / quota / route）；
  - 出站后端请求统一经 `traceHeaderForward` 携带 `X-Trace-Id` 头转发（LLaMA / LM Studio / Ollama / 云端四类后端全覆盖）；
  - 单测用 httptest 桩后端验证了「有 trace 时头被转发、无 trace 时头不出现」。
- **与审计关联、不重复存储**：trace 明细只活在**内存环形缓冲**（容量 256 条，与既有 wafLogs 同模式，重启即失、永不落盘）；持久化关联走**现有**审计/WAF 日志行尾追加 ` TRACE=<id>` 字段——不新增第二个存储文件。真进程冒烟已验证：WAF 拦截行 `[20:18:32] 127.0.0.1 GET /api/tools/file → BLOCKED (路径穿越) TRACE=3422bf78809eaa6b` 与响应头 X-Trace-Id 完全一致。
- 管理查询：`GET /api/admin/traces?limit=N`（admin.read 类，admin/auditor/team_lead/global 系可读）返回环形缓冲明细（含 spans、状态码、耗时）；响应内嵌说明字段标注「内存环形缓冲，持久关联走审计行 TRACE=」。

## 三、tsg doctor 自诊断 CLI

- 用法：`tsg doctor`（人读报告）/ `tsg doctor --json`（机器可读，summary + checks 数组）/ `tsg doctor --config <path>`。
- 退出码约定：**0** = 全过（允许 WARN）；**2** = 仅 WARN 无 FAIL；**1** = 存在 FAIL。可直接接脚本/巡检。
- 7 大类 18 项检查：**配置**（可解析/角色合法唯一/自定义密钥/审计开启）、**权限**（应用目录可写探测/gateway-key.txt 0600/config.json 非世界可写）、**端口**（18889 占用判定 + 18890 说明）、**网络**（LM Studio :1234 / Ollama :11434 可达性）、**依赖**（GGUF 模型数/llama-server/内嵌前端）、**资源**（内存 <2GB FAIL/<4GB WARN；磁盘 <1GB FAIL/<5GB WARN）、**运行态**（GET /health、GET /metrics 实测探活，探针 key 自动从 gateway-key.txt 或用户表取）。
- 每条非 PASS 项都带「→ 下一步」具体建议（例：`ollama serve`、`放入 .gguf 模型或经 /api/admin/model/download 下载`、`建议 7B 以上模型使用 Q4 量化`）。
- 配置读取用独立 JSON 解析（无 loadConfig 副作用），doctor 本身绝不改动任何状态。

## 四、Grafana dashboard 模板

- 文件：`grafana/tsg-observability-dashboard.json`（Grafana 10+，uid `tsg-observability`，23 个面板，建议刷新 30s）。
- 导入：Dashboards → New → Import → 贴入 JSON → 数据源选你的 Prometheus（模板用 `${DS_TSG}` 变量占位）。
- 四行布局：
  1. **核心指标**：QPS、p50/p95/p99、5xx 错误率、uptime、按端点类 QPS/p95 时序；
  2. **WAF 详情**：按规则命中速率与分布（饼图）、24h 总量；
  3. **模型路由分布**：按后端堆叠速率、占比环图、各后端 p95、成功率、探索次数；
  4. **资源与模块**：guard tier 状态时间轴（L0 绿→L3 红）、RSS、module_up/backend_up 状态时间轴、租户配额、build_info 表。
- 抓取配置示例（prometheus.yml）：

```yaml
scrape_configs:
  - job_name: tarssecureguard
    scrape_interval: 15s
    scheme: http
    authorization:            # /metrics 沿用网关统一鉴权
      type: X-API-Key
      credentials: <readonly 用户的 apiKey>
    static_configs:
      - targets: ["127.0.0.1:18889"]
```
