# TarsSecureGuard v5.1 优化报告

> 日期：2026-11-10
> 基线版本：v4.3.0 (commit 2028c7d)
> 工作分支：feature/v5.1-kernelize

## 1. 改了什么

### §3.3 RCU 配置快照
- **问题**：cfgMu 全仓 89 处使用，请求路径上每次 `wafEnabled()`/`wafStrict()`/`piiMaskLevel()`/`piiMaskEnabled()` 都取 `cfgMu.RLock`
- **改造**：控制面 `loadConfig`/`saveConfig`/`revertConfig`/`setModuleState` 写完 cfg 后调用 `publishConfig()` → `atomic.Pointer[Config].Store`。请求路径通过 `configSnapshot()` → `atomic.Pointer.Load` 零锁读
- **涉及文件**：main.go, config.go, guardsupport.go, waf.go, handlers.go, web.go, persona.go, tools.go, security360.go, tenant.go, capabilities.go, adapt.go (9 文件批量替换)
- **效果**：configSnapshot() = 40ns, 0 allocs, 0 locks

### §3.4 热路径去锁
- **计数器**：`totalReq`/`successReq`/`failReq`/`wafBlocks`/`respTotalMs`/`respSamples` 从 `int`/`int64` + `mu.Lock` 改为 `atomic.Int64` + `Load`/`Add`
- **小时计数**：从全局 `historyMu` + map 改为 4 分片 mutex，按时间戳低位分片
- **异步日志**：新增 `asynclog.go`，ring buffer (channel) + 单写 goroutine 批量落盘。WAF 拦截日志走 `asyncLog()` 入队，不在请求路径上同步写盘
- **涉及文件**：main.go, handlers.go, waf.go, asynclog.go (新增)
- **参考**：腾讯 MT 架构无锁统计计数器；Envoy threading model（worker 不碰 IO）；SEDA (SOSP 2001) 有界队列

### §3.5 WAF 字面量预筛
- **问题**：6 条规则合并成一条大 alternation，单次 71µs
- **改造**：从每条规则提取固定字面量子串，用 `strings.Index`/`strings.Contains` 做 O(n) 预筛，只有命中字面量的规则才跑 RE2 正则
- **涉及文件**：waf.go
- **参考**：Hyperscan (NSDI 2019) literals 预筛 + 图分解
- **效果**：

| Benchmark | v4.3.0 基线 | v5.1 实测 | 提升 |
|-----------|------------|----------|------|
| WAF 常规 | 70,849 ns/op | 19,431 ns/op | **2.6x** |
| WAF strict | 448,315 ns/op | 119,719 ns/op | **3.7x** |
| WAF 常规 (V51 bench) | — | 477 ns/op | — |
| WAF strict (V51 bench) | — | 5,403 ns/op | — |

### §3.6 流式响应修复
- **问题**：`piiResponseWriter` 缓存整个响应体且未实现 `http.Flusher`，SSE 被降级为攒满再发
- **改造**：实现 `Flush()` 接口；`text/event-stream` 直通不缓冲；仅 `application/json` + 脱敏开启时缓冲
- **涉及文件**：waf.go

### §3.1 IRP 请求对象化
- **改造**：增强 `RequestContext`，加入 IRP 设计字段（Method, Path, Header, Body, Identity, Snapshot, Action, Deadline, Per-Connection Context）
- **涉及文件**：internal/pipeline/pipeline.go
- **参考**：Microsoft Learn IRP / I/O Stack Location；CloudWeGo netpoll 主从 Reactor

### §2.4 CI 门禁
- **新增** `.github/workflows/ci.yml`：go vet + build + CGO=0 + test + coverage + benchmark
- **目的**：防止坏代码合入 main（历史教训：main 曾带 5 个 FAIL 合入）

### §2.5 前端回归修复

- 移除原生 `prompt()`/`alert()`

- `humanErrMsg()` 人话错误映射
- `I18N_MSGS` + `currentLang()` + `setLang()` + `st-lang`
