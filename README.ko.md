# 🛡️ TarsSecureGuard

### AI 시대의 라우터 &amp; 설정기 —— AI 시대의 라우터와 설정기, 안전 벨트 기본 탑재

<p>
<b>압축 해제만으로 사용 가능</b> · <b>높은 보안성</b> · <b>설정 불필요</b> · <b>전 플랫폼 호환</b> · <b>모든 것을 연결</b> · <b>다른 AI 도구까지 대신 설정해줌</b>
</p>

<p>
의존성 제로, 단일 파일, 완전 정적 형태의 <b>로컬 AI 게이트웨이</b>입니다: 왼쪽으로 13종의 AI 소프트웨어 클라이언트를 연결하고（Claude Desktop / Cursor / Cline / Continue / Windsurf / Codex CLI / Warp / Cody / JetBrains / Tabnine / Zed / Roo Code / VS Code Copilot）, <br/>

중간에서 WAF, 시맨틱 보호, 계층별 제한, IP 신뢰도, RBAC, 감사 및 PII 익명화를 강제로 활성화합니다——<b>많이 연결하는 것보다 안전하게 지키는 것이 더 중요합니다</b>.
</p>

<b>단순한 게이트웨이가 아니라 설정기입니다（v3.7.0 Extender）</b>: 다른 AI 도구의 환경 설정이 복잡한가요? TSG가 대신 설정해드립니다——내장 탐지기가 기기에 설치된 <b>OpenClaw / Continue / Aider / Cline / ZooCode / Codex CLI</b>를 스캔하고,

## 📣 추천사

> **모든 AI 클라이언트가 각자의 비공개 모델 생태계를 가지고 있을 때, TarsSecureGuard는 OpenAI 호환 키 하나만으로 모든 모델, 모든 도구, 모든 프로토콜을 연결할 수 있게 해줍니다——그리고 강제로 안전 벨트를 착용시켜줍니다.**
>
> 압축 파일을 다운로드하고 압축을 푼 뒤 더블 클릭만 하면 로컬 포트 `18889`에서 서비스가 시작되고 브라우저에서 자동으로 한국어 관리 패널이 열립니다. 1GB짜리 이미지를 받거나 MySQL을 설치해야 하는 "무거운 게이트웨이"가 아니라 **의존성 제로, 완전 정적, USB에 넣어서도 실행할 수 있는** 가벼운 보안 게이트웨이입니다.
>
> v3.2.0에서는 "연결"을 극한으로 끌어올렸습니다——**Coding Plan 하나의 키로 모든 모델에 접근**할 수 있습니다; 50개 통합 로드맵이 이미 마련되어 있습니다; 오픈소스 / 클로즈드소스 / CLI 세 가지 통합 모드를 지원합니다（**embed 내장 / federate 연합 / wrap-cli-as-mcp 래핑**）; 일시적으로 연결할 수 없는 경우 실행 가능한 연동 가이드를 제공합니다.
>
> 다른 게이트웨이가 아직 YAML을 설정하고 라우팅 규칙을 디버깅하라고 요구할 때, TarsSecureGuard는 이미 안전 벨트를 채우고 클라이언트를 연결한 뒤 키를 당신 손에 쥐여줍니다.

## 🌟 소개글

TarsSecureGuard는 **로컬 우선(local-first) AI 게이트웨이——AI 시대의 라우터**입니다. 당신과 모든 AI 기능 사이에 위치하며: 왼쪽에는 당신의 AI 소프트웨어（Claude Desktop、Cursor、Cline、Windsurf、Codex CLI……원하는 것을 선택）가 있고, 오른쪽에는 24개의 클라우드 모델 제공사 + 8종의 로컬 추론 런타임（자유롭게 연결）이 있습니다; 외부로는 OpenAI 호환 엔드포인트（HTTP 또는 **stdio**）+ MCP를 노출하고, 내부적으로는 통합 스케줄링, 통합 관리, 통합 감사를 수행합니다.

> 집에 있는 라우터는 랜선을 생산하지도 않고 웹사이트를 만들지도 않지만, 모든 기기가 안전하게 인터넷을 사용할 수 있게 해줍니다. TarsSecureGuard는 모델을 생산하지도 않고 특정 클라이언트 사용을 강요하지도 않습니다——**모든 AI 클라이언트가 모든 모델을 안전하게 사용할 수 있게 해줄 뿐입니다.** 우리는 이 일을 극한까지 할 계획입니다: 연결할 수 있는 것은 모두 연결하고, 일시적으로 연결할 수 없는 경우 실행 가능한 연동 가이드를 제공합니다（`docs/v3.2.0-unconnectable.md` 참고）.

### v3.2.0 신규 기능 · Universal Connector 로드맵

> **하나의 Coding Plan 구독 키 = 모든 모델의 열쇠**입니다. TSG는 각 provider의 차이를 OpenAI 호환 레이어 뒤에 숨겨서, AI 클라이언트를 재작성할 필요도 없고 사용자가 도구를 전환할 필요도 없습니다.

전 세계 모든 AI 소프트웨어（직접 연결할 수 없는 오픈소스 / 클로즈드소스 / CLI 도구 포함）를 TSG에 통합하는 세 가지 **통합 모드**:

| 모드 | 적용 대상 | 방법 |
|---|---|---|
| **embed（내장）** | 오픈소스 라이브러리（C/C++/Go/Rust/Python）| 코드를 TSG 프로세스 내에 컴파일하여 직접 호출（예: ggml / whisper.cpp / sqlite-vec）|
| **federate（연합）** | 원격 서비스 / API 게이트웨이 | TSG 리버스 프록시 + 프로토콜 어댑터를 통해 통합 스케줄링（각 MCP Hub, 서드파티 API 플랫폼）|
| **wrap-cli-as-mcp（CLI를 MCP로 래핑）** | 모든 명령줄 도구 | 코드 작성 없이 MCP 서버로 래핑하여 AI가 TSG를 통해 간접 호출（예: ripgrep / fd / magika / jq）|

**현재 진행 상황**: 24개 클라우드 provider + 8개 로컬 런타임（내장 등록, 각 provider별 기계 판독 가능 문서 제공）, 13개 클라이언트 연동 가이드, 17개 일시적 미연결 항목（v3.3.0 목표 50개 통합）. **새로운 provider 추가시 코드 수정 없이 설정만으로 가능**합니다——이것이 v3.2.0이 "라우터" 역할을 할 수 있는 이유입니다.

| 특징 | 설명 |
|------|------|

## 🧩 v3.0.0 기능 목록（"Your AI's Safety Belt"）

### A 라인 · 리소스 가디언（resourceGuardian）
- `GOMEMLIMIT` 소프트 메모리 상한（min(물리 메모리 10%, 384MB), eco 모드는 128MB, 덮어쓰기 가능）.
- **L0–L3 계층별 응답**: L1 비핵심 기능 다운그레이드 → L2 고부하 기능 서킷 브레이커 → L3 정상 종료（30초 드레인 + 감사 로그 디스크 기록 + 상태 저장 + 종료 코드 42 + 쿨다운으로 스톰 방지）.
- L2/L3은 **RSS 기준**으로 판정하여 CGO / 외부 메모리 누수를 포착합니다; eco 저전력 모드는 저사양 하드웨어에 자동 적용됩니다.

### B 라인 · 보안 업그레이드
- **시맨틱 감지 계층별 분류（semanticGuard）**: 정적 규칙을 먼저 적용하고, 회색 구역은 로컬 0.5B–1.5B 소형 모델이 판단합니다; **fail-close 철칙**——엔진을 사용할 수 없으면 직접 503을 반환하며 절대 통과시키지 않습니다; 지문 캐시 + 회색 구역 속도 상한 적용.
- **3차원 토큰 버킷 트래픽 제한（rateLimiter）**: IP×엔드포인트 유형 / Key×엔드포인트 유형 / IP 총량, 제한 초과시 429를 반환하고 신뢰도 점수 차감과 연동합니다.
- **로컬 IP 신뢰도（ipReputation）**: 기본 점수 100점, WAF/스캔/트래픽 제한 위반시 점수 차감, 저점수는 자동 차단, 화이트리스트 지원, 24시간 자동 복구, NAT 이상 알림, admin이 차단 해제 가능.
- 「**AI는 오직 강화만 가능**」단방향 병합 철칙: 보안 정책은 더 엄격해지는 것만 허용하며, 100% 단위 테스트 + 런타임 감사 적용.

### C 라인 · 2단계 인텔리전트 라우팅
- **smartRouter**: 정적 규칙을 우선적으로 적용하고 **ε-greedy bandit**（ε 0.1→0.02 감소）를 통해 성공률/지연 시간 이력에 따라 자동으로 최적 백엔드를 선택합니다; admin이 아닌 사용자의 피드백은 가중치를 낮춰 위조를 방지합니다.
- **scoreBoard**: 런타임 점수（성공률×지연 시간）에 **lm-eval-harness** 오프라인 평가를 융합합니다（상대 참고, 정직한 라벨링; Python 사이드카는 필요시에만 사용, 묶이지 않음）.

### D 라인 · 생태계 차원 상승
- **`--mcp-stdio`: stdio를 통한 JSON-RPC 2.0 지원**, 모든 로컬 에이전트가 연결만 하면 전체 보안 기능을 즉시 사용할 수 있습니다——이번 버전의 핵심 차별점입니다.
- 도구: `tars_guarded_chat` / `tars_guard_status` / `tars_route_preview` / `tars_model_score` / `tars_module_schema` / `tars_ip_reputation_unban`; 관리 작업은 `TSG_ADMIN_KEY`가 필요하며 전 과정 감사됩니다.

### E 라인 · 안정성 엔지니어링
- panic recovery 전체 커버; Go fuzzing（WAF / 설정 파싱 / 시맨틱 정규화）; **8시간 soak 부하 테스트 스크립트**（`soak.sh` / `soak.ps1`）; 단위 + httptest 통합 테스트 `-race` 전부 통과.

### 플랫폼 및 제공
- UI 전체 한국어 지원; **배포 파일 완비**: systemd 유닛, Dockerfile, docker-compose（rootless）, K8s sidecar 예시, macOS LaunchDaemon（[`deploy/`](./deploy) 참고）.
- `go.mod`에 서드파티 의존성이 전혀 없고 모두 표준 라이브러리만 사용합니다——**공급망 공격 표면 제로**.

## 🥊 최대 경쟁사 분석

**결론: 현재 가장 규모가 크고, 가장 적극적으로 대응해야 할 경쟁사는 LiteLLM입니다** (오픈소스 AI 게이트웨이 사실상 표준, 약 6만 Star, 생태계와 인지도가 가장 높음); 국내 시장에서는 **New API / One API**가 Go 기술 스택의 인지도 리더입니다; "로컬 우선" 포지셔닝에서는 **OmniRoute**가 가장 유사합니다.

| 경쟁사 | 강점 | TarsSecureGuard 대비 약점 |
|------|------|----------------------------|
| **LiteLLM** (최대 경쟁사) | 제공사 커버리지가 가장 넓고 생태계가 성숙함, 가상 키/예산/재시도 기능이 완벽함, 해외 인지도 1위 | Python 기술 스택으로 배포 부담이 크다 (Postgres + Redis 필요, 이미지 500MB+, 전체 구성 시 거의 1GB); 클라우드 모델 중심 설계; 보안이 기본 판매 포인트가 아님; 단일 파일로 압축 해제만으로 사용 불가; 시맨틱 fail-close / 리소스 가드 기능 없음 |
| **New API / One API** (국내 인지도 높음) | Go로 개발됨, 국산 모델 전부 지원, 채널/토큰/과금/충전 운영 링크가 완전함 | "API 리셀/운영 과금"에 포지셔닝되어 MySQL + Redis 필요; 파라미터가 복잡함; 로컬 모델 / 단일 서버 보안 시나리오를 위해 설계되지 않음 |
| **OmniRoute** (로컬 우선) | 명확한 local-first 포지셔닝, Star 증가 속도 빠름, 자동 다운그레이드와 다중 라우팅 전략 지원 | "다중 공급자 집계 라우팅"에 치중되어 보안 거버넌스 (WAF/시맨틱/RBAC/제한/IP 신뢰도/감사/PII)가 핵심 기능이 아님; 단일 파일 제로 의존성 내망 규정 준수를 주장하지 않음 |
| **LM Studio / Ollama + OpenWebUI** ("충분히 쓸만한" 대안) | 사용자가 이미 설치해 사용 중, GUI가 친숙함, 모델 찾기 편리함 | 이들은 거버넌스 게이트웨이가 아닌 **런타임**입니다: WAF, 시맨틱 보호, 트래픽 제한, IP 신뢰도, RBAC, 감사, 리소스 가드를 제공하지 않으며 —— TarsSecureGuard가 정확히 이 계층을 관리하고 보완합니다 |

**차별화 전략**: "제공사 수"로 경쟁하지 않고, 개인과 내망에서 매우 고통스럽게 여기지만 간과되었던 시장 틈새를 차지합니다 —— **「제로 설정 + 단일 파일 + 보안 기본 활성화 + 로컬 우선 + stdio 플러그 앤 프로텍트」**. 중량급 게이트웨이는 플랫폼 팀을 갖춘 대기업을 서비스 대상으로 하고; TarsSecureGuard는 "오늘 당장 로컬 AI를 안전하고 안정적으로 사용하고 싶은" 개인, 테크니컬 유저와 격리된 내망을 서비스 대상으로 합니다.

## 🏰 가장 깊은 해자 분석

**결론: 가장 깊은 해자는 「Security Core」가 축적한 신뢰 자산과 LLM 보안 방어 지식 베이스이며, 「제로 의존성 단일 파일」의 제로 공격 표면 엔지니어링으로 지속적으로 강화됩니다; v3.0의 MCP stdio는 이 보안 체계를 접속과 함께 자동으로 배포해 해자를 더욱 넓힙니다.**

해자는 얕은 곳에서 깊은 곳으로 3계층으로 나뉩니다:

1. **엔지니어링 간결성 계층 (복사 쉬움, 단기 우위)**: 제로 서드파티 의존성, 순정적 단일 파일, 6개 플랫폼 지원, 리소스 가드와 스마트 라우팅. 경쟁사가 모방할 수는 있지만, 장기적으로 절제하고 생태계를 포기해야 하므로 대부분의 팀이 할 수 없습니다.

2. **보안 지식 계층 (핵심 장벽, 시간이 지날수록 복리 증가)**: Security Core는 **LLM에 특화된 전체 방어 자산**입니다 —— WAF와 Prompt 인젝션/탈옥 특징, 시맨틱 그레이 존 판단 (fail-close), IP 신뢰도 행동 지문, 3차원 트래픽 제한, PII 패턴과 비식별화, SSRF 5가지 금지 규칙, 방화벽 연동, 감사 체계, 그리고 "탐지율 vs 오탐율"의 지속적인 튜닝. **실제 샘플이 많을수록 → 규칙이 정확해짐 → 오탐이 줄어듦 → 사용자가 늘어남 → 샘플이 더 많아짐**의 자기 강화 플라이휠이 작동하므로, 후발 주자가 코드를 한 번 복사하는 것으로는 따라잡을 수 없습니다.

3. **신뢰와 배포 계층 (가장 깊고 복사 가장 어려움)**: 보안 제품의 최종 장벽은 **"한 번도 사고가 나지 않은" 신뢰 기록**과 규정 준수 인지도입니다; "보안은 영구적으로 끌 수 없고 / AI는 보안 강화만 가능하다"는 설계 약속이 기본 선택으로 자리 잡습니다. v3.0의 **stdio 플러그 앤 프로텍트**는 어떤 로컬 에이전트든 접속만 하면 전체 보안 체계를 상속받는다는 의미입니다 —— 보호 기능이 접속과 함께 자동으로 확산되어 **배포 플라이휠**을 형성합니다. 구독 버전은 지속적인 보안 업데이트와 SLA로 신뢰를 수익화합니다. 신뢰는 한 분기 안에 구축할 수 없고, 가격 경쟁으로 파괴할 수도 없습니다.

> **솔직한 판단**: 프로젝트가 성장기에 있으므로 해자는 여전히 "넓어지는 중"입니다 —— 기능层面은 복사될 수 있습니다. 진정한 너비는 **사용량이 가져다주는 방어 데이터 + stdio 배포 플라이휠 + 장기 무사고 신뢰 기록**으로 결정됩니다. 구독 버전의 전략적 가치는 바로 "지속적인 보안 업데이트"를 복리가 가능하고, 과금이 가능하며, 신뢰를 축적할 수 있는 자산으로 만드는 것입니다.
